# 공공 AI 입찰 분석 에이전트 (Public Bid Agent)

> **프로젝트 상태: 애자일 Sprint 1 개발 브랜치 구현 중 (공개 배포 미완료)**  
> React/TypeScript + FastAPI 합성 공고 검색·상세 조회 코드와 pytest 테스트가 작성되었습니다. 로컬 백엔드 테스트 11개는 통과했으나 프런트엔드 빌드·별도 독립 검수·공개 배포는 미완료입니다. 실제 나라장터 API 및 AI 추론은 아직 연결하지 않았습니다.

## 프로젝트 소개

나라장터에 공개된 AI 및 소프트웨어 관련 입찰공고를 검색하고, 공고문과 제안요청서(RFP)의 참가요건 및 기술 요구사항을 분석하여 사용자 또는 기업의 참여 적합성을 **공식 원문 근거와 함께 제시하는 웹서비스**를 개발하는 프로젝트입니다.

단순히 공고를 나열하는 대신, 사용자가 어떤 사업을 우선 검토해야 하는지 판단하는 데 필요한 정보와 추가 확인사항을 정리하는 것을 목표로 합니다.

## 해결하려는 문제

공공 SW 사업을 검토하려면 여러 공고를 검색하고 첨부 문서를 열어 참가자격, 요구 기술, 사업기간, 마감일 등을 일일이 확인해야 합니다. 이 프로젝트는 반복적인 탐색과 문서 분석을 지원하되, AI의 판단을 공식적인 입찰 자격 판정으로 오인하지 않도록 설계합니다.

## 주요 기능 계획

1. **입찰공고 탐색:** 조달청 나라장터 공개 API를 통해 AI/SW 관련 공고 검색
2. **공고 및 문서 분석:** 공고문, 제안요청서, 규격서에서 참가요건과 기술 요구사항 추출
3. **기업 역량 비교:** 사용자가 등록한 기술 및 기업 조건과 공고 요구사항 비교
4. **추가 확인사항 질문:** 판단에 필요한 정보가 없으면 사용자에게 확인 요청
5. **근거 기반 결과 제공:** 적합, 추가 검토 필요, 부적합으로 구분하고 공식 출처 연결
6. **사용자별 관리:** Google 로그인 및 사용자별 프로필·분석 기록 관리

위 항목은 모두 **구현 예정 기능**이며 현재 동작을 검증한 기능이 아닙니다.

## 사용자 이용 흐름

```text
Google 로그인
    ↓
기업 정보 및 기술 역량 등록
    ↓
나라장터 공개 입찰공고 검색
    ↓
AI/SW 관련 공고 선별
    ↓
공고문 및 제안요청서 분석
    ↓
참가요건과 기술 적합성 비교
    ↓
부족한 정보가 있으면 추가 질문
    ↓
판단 결과와 공식 원문 근거 제공
```

## 기술 구성 계획

| 구분 | 기술 | 적용 목적 |
|---|---|---|
| 웹 화면 | React, TypeScript | 검색, 조건 입력, 분석 결과 표시 |
| 백엔드 | Python, FastAPI | API, 인증·인가, 외부 데이터 연계 |
| AI 작업 흐름 | LangGraph | 검색·분석·검증·추가 질문 단계 관리 |
| AI 및 문서 검색 | LangChain, RAG | 공고문과 제안요청서의 관련 근거 검색 |
| 데이터베이스 | PostgreSQL, pgVector | 공고·사용자·분석 결과와 검색용 데이터 저장 |
| 외부 도구 연계 | MCP | 공공데이터 조회 도구의 연결 경계 |
| 로그인 | Google SSO | 사용자 인증 |
| AI 추론 | Codex 검토 중 | 공식적으로 허용되는 인증·배포 방식 확인 후 적용 |
| 실시간 응답 | SSE | 분석 진행상황 전달 |
| 배포·검증 | Docker Compose, pytest, GitHub Actions | 실행환경 및 자동 검증 |

기술 구성은 목표 설계이며, 필요성과 공식 지원 여부를 검증한 뒤 확정합니다. 초기에는 공개 공고 검색과 PDF 근거 추적을 먼저 검증하고, LangGraph·pgVector·MCP·SSE는 실제 필요를 확인하며 순차 도입합니다.

**모델 연결 제한:** ChatGPT 플랜 기반 오픈소스 로컬 사용과 공개 원격 호스팅 서비스의 권한은 다릅니다. 공개 웹서비스에서 사용자별 ChatGPT/Codex 사용이 공식적으로 허용되는지 확인하기 전까지 실시간 AI 추론 기능을 제공한다고 주장하지 않습니다. 별도 종량제 API 키 제공을 사용자에게 요구하지 않는 방향을 유지합니다.

공고문, 제안요청서, 첨부파일 등 제3자 자료의 권리는 각 원 출처에 있으며, AI가 생성한 분석과 원문 자료를 구분하여 표시하도록 설계합니다.

## 구현 범위와 제한사항

이 프로젝트는 **공개 입찰정보 탐색과 참여 가능성 검토를 지원**합니다.

실제 입찰서 제출, 공동인증서 서명, 결제, 계약 체결 및 법적 참가자격의 최종 확정은 수행하지 않습니다. AI 분석 결과는 공식 공고와 관계기관의 판단을 대체하지 않습니다.

## 개발 원칙

- **워터폴식 전체 설계 완료 대기 대신 애자일 반복 개발**: 공고 검색부터 작게 구현하고 테스트·검수·개선을 반복합니다.
- 기능별로 필요한 계약과 위험만 먼저 설계하고, 기존 ADR은 구현·검증 결과에 따라 보완합니다.
- GitHub 공개 소스코드 작업과 사용자 대상 실제 서비스 배포 승인은 별도로 관리합니다.
- 주요 소스 파일 상단에 한글 설계 계약을 작성합니다.
- React, TypeScript, FastAPI 공식 문서 및 OWASP 보안 지침을 기준으로 코드를 검토합니다.
- AI가 작성한 코드도 테스트와 독립 검토를 거칩니다.
- 회사·고객사의 비공개 코드, 데이터, 인증정보를 사용하지 않습니다.
- 구현 예정, 구현 완료, 테스트 통과, 실제 배포 상태를 구분합니다.

현재 Sprint 1은 **React + FastAPI + 합성 fixture 공고 검색/상세 UI + 공식 API 구조 검증 + 최소 CI**입니다. 개발 브랜치 구현 내용과 재현 절차는 [Sprint 1 실행 문서](docs/implementation/SPRINT1_RUNBOOK.md)에서 확인할 수 있으며, [다른 채팅·AI용 지속 지시서](docs/implementation/CONTINUE_IMPLEMENTATION_PROMPT_2026-10-09.md)에 사용자 요구 원문을 보존합니다. 이후 원문·기술 적합성·AI 연동·사용자 서비스화를 필요한 순서로 확장합니다. 로그인·외부 AI 추론·개인정보를 사용하는 기능은 해당 위험 검증 후 공개합니다.
