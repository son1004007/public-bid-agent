# 07 애자일 개발 및 검수 작업 기준

- 채택일: 2026-10-09
- 적용: `public-bid-agent`의 요구사항, 구현, 테스트, 검수, 백로그 및 배포
- 결정: **워터폴식 전체 상세 설계 완료와 무한 재검수를 구현의 선행조건으로 삼지 않는다.**
- 기존 `AGENTS.md`, 중앙 `CONTROL.md`, `personal-engineering-handbook/REVIEW_POLICY.md`의 보안·독립 검수 의무를 폐기하지 않는다.

## 1. 개발 원칙

1. **사용자 가치부터 구현**: 입찰공고 검색 → 원문 근거 → 기술 적합성 비교 → 검증된 AI 분석 → 로그인·운영 서비스의 순서로 작은 기능을 제공한다.
2. **작은 수직 슬라이스**: UI·API·데이터·오류 처리·테스트를 하나의 사용자 흐름으로 연결한다. 문서·인터페이스만 완성하고 기능 완료로 선언하지 않는다.
3. **점진적 설계**: 현재 구현에 필요한 최소한의 설계 계약을 먼저 확정한다. 미래 기능은 ADR과 백로그에 보존하되 기능 구현 전에 구체화한다.
4. **피드백과 개선**: 동작·실제 API 응답·사용자 판단·테스트 결과를 근거로 설계를 수정하고 다음 우선순위를 조정한다.
5. **보안의 개발 내재화**: secret 비노출, 권한 경계, 불신 데이터 검증, 실제 입찰 자격 오인 방지는 처음부터 적용한다. 운영용 고급 통제는 관련 기능을 활성화하기 전에 검증한다.
6. **증거 기반 완료**: 문서/AI 리뷰 결과와 실제 실행·테스트 성공은 다르며, 완료·출시 주장은 실행 증거로만 한다.

## 2. 반복 개발 흐름

```text
CURRENT_STATE / TASKS / 사용자 요구 확인
  -> 이번 반복의 사용자 시나리오 1개 선택
  -> 필요한 요구사항·계약·위험·수용기준만 확인
  -> 구현과 자동 테스트 작성 (작은 단위 커밋 가능)
  -> 로컬 실행 및 오류·경계 확인
  -> 변경 단위 독립 검수 / 지적사항 판정
  -> 필요한 수정 및 회귀 테스트
  -> 상태·백로그·필요한 ADR 갱신
  -> 다음 반복
```

- 시간이 정해진 스프린트보다 **검증 가능한 결과물 단위**를 우선한다.
- 진행 중 발견한 새로운 요구와 위험은 현재 범위에 꼭 필요하지 않으면 백로그로 옮긴다.
- 구현 중 가설을 바꾸는 경우 문서 전체를 다시 작성하지 않는다. 관련 계약·테스트만 갱신한다.
- 실제 기능이 위험하거나 기존 정책과 모순되면 해당 부분만 중지하고 증거를 확보한다.

## 2.1 2026-10-09 UI 퍼블리싱 우선 적용

사용자의 최신 지시로 **설계 → 퍼블리싱 시안 → 사용자 직접 화면 검증 → 수정 → 백엔드 상세 구현** 순서를 우선한다. 이는 애자일 반복 개발과 양립하며 서버·보안 검증을 UI 검증으로 대체하지 않는다. 현재 시안은 `frontend/public/ui-review.html`이며 [화면 검증 가이드](ui/SCREEN_REVIEW_GUIDE.md)를 적용한다. 사용자 승인 전에는 `UI_APPROVED`로 표시하지 않는다. 기존 서버 코드는 삭제하지 않되 후속 API 구현의 선행 작업으로 확대하지 않는다.

## 3. 스프린트 로드맵 (우선순위는 조정 가능)

| 단계 | 사용자에게 확인할 수 있는 결과 | 초기 범위 |
|---|---|---|
| Sprint 1 | 공고를 검색하고 상세를 열어 본다 | React + FastAPI, 합성 fixture, 공식 API 스키마 검증, 기본 테스트/CI |
| Sprint 2 | 문서의 요건과 공식 원문 위치를 본다 | 허용된 PDF 수집·격리 파싱, 필수조건·출처/부분 추출 표시 |
| Sprint 3 | 기술 역량과 공고를 비교해 우선순위를 판단한다 | 비민감 프로필, 기술 적합도, 행정 참가자격 미검증 분리 |
| Sprint 4 | 실제 승인된 AI 분석의 결과를 검증한다 | 공식 허용된 모델 경로, 평가, 호출 제한; RAG/LangGraph는 필요할 때만 |
| Sprint 5 | 사용자별 이력과 공개 서비스를 안전하게 사용한다 | Google OIDC, 리소스 격리, 삭제·운영/배포 검증 |

- Sprint 1은 로그인 없이 **민감정보를 저장하지 않는 로컬 검색·상세 조회**로 시작한다.
- 실제 AI 호출이 승인되지 않으면 Sprint 4는 `disabled` 상태로 유지한다. 사용자가 유료 종량제 API 또는 로컬 모델로 자동 전환되지 않도록 한다.
- 스프린트 순서는 기능 의존성·실제 API 결과·사용자 피드백에 따라 재배열한다.

## 4. 작업 단위 완료 조건 (Definition of Done)

논리적 기능 변경 단위마다 다음을 확인한다.

- 요구사항/사용자 시나리오와 범위가 명확하다.
- 실제 코드가 해당 시나리오를 동작시키고, 정상·대표 오류·필수 보안 경계 테스트를 실행했다.
- 테스트/실행 환경/커밋 SHA/성공·실패 결과를 재현 가능한 수준으로 기록했다.
- 비밀정보, 민감 자료, 원문 출처·해석 혼동이 없는지 확인했다.
- 의미 있는 변경은 `REVIEW_POLICY.md`에 따른 **독립 최종 리뷰**를 받고 남은 finding을 판정했다. 중요 설계는 정책에 맞는 사전 검수도 적용한다.
- `CURRENT_STATE.md`, `TASKS.md`, 필요 시 ADR/README를 실제 결과로 갱신했다.
- 공개 서비스에 배포할 기능이라면 별도 릴리스 게이트도 통과했다.

**미완료의 정확한 표시:** `PLANNED`, `IN_PROGRESS`, `IMPLEMENTED_UNVERIFIED`, `VERIFIED`, `REVIEWED`, `RELEASED`. 검수·테스트가 없으면 단순 코드 커밋은 `REVIEWED` 또는 `RELEASED`가 아니다.

## 5. 독립 검수의 적용 범위

- 기존 Codex R1~R4 의견은 **원시 위험 정보**이며 모든 구현의 선행 승인 목록이 아니다.
- 구현 중 매 파일/매 커밋마다 별도의 독립 리뷰를 요구하지 않는다. `REVIEW_POLICY.md`의 **논리적 변경 단위**에 적용한다.
- 개인/AGY 승인 환경에서의 AGY/Gemini 검수 의무, 유효한 대체 검수자·검수 부채·분쟁 조정은 상위 정책을 따른다. 이 문서는 상위 규칙을 임의 완화하지 않는다.
- 코딩 후 발견한 실제 문제는 증거에 따라 중요도와 범위를 보정한다. 해결된 위험은 자동 재분류하지 않고 처리 근거를 남긴다.
- 신규 이슈로 문서 전체를 무한히 재검수하지 않는다. 미해결 쟁점은 변경 가능한 증거·수행할 실험·중단 조건을 정해 제한적으로 조사한다.

## 6. 개발과 공개 운영의 별도 게이트

| 활동 | 규칙 |
|---|---|
| 공개 GitHub 코드·문서 기록 | 작업 중 코드 기록 가능. secret/개인정보/제3자 원문 무단 공개 금지 |
| 로컬 합성 fixture PoC | 전체 설계 승인을 기다리지 않고 구현 가능. 실제 API·AI 성공이라고 표기 금지 |
| 공식 공개 API 접속 | 출처 이용조건, 실제 API 스키마, 오류/조회 한도 및 비밀정보 관리 확인 후 |
| PDF 다운로드·파싱 | 공식 제공처·SSRF/자원 상한·격리와 법적 재사용 범위 검증 후 |
| Google 로그인·사용자별 데이터 | OIDC/CSRF/소유권/삭제와 필요한 E2E·독립 검수 후 활성화 |
| 실제 AI 원격 추론 | 공식 사용자별 인증/배포 허용, 입력 정보·동의, 비용 및 사용량 제한 검증 후 |
| 공개 서비스 배포 | 실제 활성 기능 전체의 테스트·보안·운영·독립 검수와 사용자 승인 후 |

미구현 기능은 비활성화하며, 해당 기능의 보안 검증을 '완료'로 기록하지 않는다. 기존 `docs/04-operation-and-deployment.md`의 공개 배포 체크리스트는 폐기하지 않는다.

## 7. 기록 방식

- `TASKS.md`: 스프린트 작업/체크리스트와 후순위 위험 백로그
- `CURRENT_STATE.md`: 실제 코드·CI·실행·리뷰·배포의 최신 증거
- `docs/01-requirements.md`: 사용자 행동/수용 기준. 실제 구현과 충돌 시 작은 범위로 정합화
- `docs/02-architecture.md` 및 `docs/adr/`: 설계 기준선과 중요한 변경 결정
- `docs/03-test-plan.md`: 활성 기능의 시험과 근거. 미실행/미적용 명확히 구별
- `docs/04-operation-and-deployment.md`: 외부 사용자 대상 출시의 별도 게이트

## 2026-10-10 UI 퍼블리싱 이후 단계 전환

사용자의 최신 구현 지시에 따라 `/decision-preview` 시안의 판단기준·12개 가중치만 로컬 JSON 백엔드로 연결한다. 초기 UI 승인 대기 문구는 현재 단계의 전체 백엔드 개발 금지가 아니라 퍼블리싱 우선순위를 의미한다. 이 작업은 합성 데이터·로컬 전용으로 범위를 제한하며 독립 최종 검수 및 UI 사용자 승인이 완료되기 전 main 병합·공개 배포는 금지한다. 실제 입찰공고 수집과 AI 호출은 후속 독립 스프린트로 유지한다.
