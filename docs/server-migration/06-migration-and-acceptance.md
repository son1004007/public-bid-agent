# 06. 이관·검증·운영 계획과 다음 작업

[전체 목차](README.md)

## 1. 단계별 실행 카드

| 카드 | 범위 | 선행/종료 근거 |
|---|---|---|
| SM01 | 확정 스택·조직 정책 연결·화면/인증/데이터 설계 | 이번 문서 산출물. 설계 검수/미정 목록 정리, 구현 완료 아님 |
| SM02 | 격리 Django/React/PostgreSQL 개발 골격·CI | 지원 버전/라이선스 고정, 합성 health/DB migration/빌드 |
| SM03 | DB 사용자·세션·최초 암호 변경·권한 | 관리자 발급/로그인/강제변경/세션폐기/타 사용자 음성 E2E |
| SM04 | 공고/원본 버전 저장·읽기 전용 JSON 이관 도구 | 샘플 이관 dry-run·ID/FK/SHA/이력·원본 불변 검증 |
| SM05 | 기존 업무 서비스 재사용·워커/일정·명시 작업 UI | outbox/중복/오류·권한·취소/재시작·재시도 상한 |
| SM06 | 목록/상세/검수/회사 근거/판단 화면 수직 연결 | 세 유형/범위 지표·권한·390/1440 회귀 |
| SM07 | 승인된 서버 staging 이관·복구 리허설 | DB/파일 동세대 복원, 세션/키 분리, 새 서버 인수 |
| SM08 | 책임자 승인 후 운영 전환 | 서비스 정지/최종 증분/무결성/사용자 인수·rollback 기준·기존 환경 보존 |

한 번에 한 카드만 구현한다. 자동 실행 하네스의 기존 H02 작업과 서버 제품 전환을 혼동하지 않는다. 자동 하네스 문제 전체가 끝날 때까지 제품 설계/합성 개발을 기다리지는 않되, 동일 파일 동시 수정/중복 worker 실행은 금지한다.

## 2. 이관 절차

1. 실제 데이터/첨부/설정/기존 검수·판단 이력의 위치·크기·권한을 점검한다. 과거 건수를 현재값으로 재사용하지 않는다.
2. 원본 전체 snapshot과 SHA manifest를 저장한다. key/암호/회사 원문을 공개 artifact에 넣지 않는다.
3. 기존 JSON을 읽기 전용으로 검증하고 PostgreSQL staging으로 dry-run 한다. `source_snapshot_id + legacy_id` 매핑을 기록하고 재실행 시 중복 생성하지 않는다.
4. 공고/문서/버전/FK/중복/검수/판단 이력 건수와 해시·범위를 대조한다. 불명한 출처/최신성/차수는 보류로 유지한다. 사용자 JSON에 임의 암호·소유자를 추정해 넣지 않는다.
5. 기존 자료의 회사/부서/담당자 귀속을 사람이 확인한 뒤 ACL을 부여한다. 계정 없이 생성된 과거 이력의 실제 작성자를 임의 계정으로 조작하지 않는다.
6. staging에서 복원과 사용자 인수 후 운영 전환을 승인받는다. 전환 시 원본 쓰기를 통제하고 최종 차분을 반영한다. dual-write를 즉흥 추가하지 않는다.
7. 성공/실패 판단 기준과 rollback 가능 시점을 명시한다. 전환 후 새 데이터가 쌓였으면 구버전 파일을 덮어써 복구하지 말고 신규 변경 보존/대조 계획을 적용한다.

## 3. 검증과 종료 기준

- 단위: 공고 상태/날짜·취소 보존, 문서SHA/버전, TP/FP/FN·정답0, 권한·계정 상태/강제변경.
- 통합: 실제 PostgreSQL unique/FK/행 잠금·동시 검수/암호 변경·중복 작업/outbox, DB/broker/파일 장애.
- 보안: 미인증/권한 없는 API·파일·관리자 경로, 최초 변경 우회·CSRF·암호/키/개인정보 비노출·유한 로그인 제한.
- 워커: timeout/메모리/오류/취소/worker 중단/재시작·재전달·허가 철회. 조회가 작업을 실행하지 않음.
- 화면: 로그인→최초 변경→재로그인→범위 내 목록→원본/정답 비교→명시 저장·충돌→판단·이력. Chrome390/1440·빈 결과/오류/세션 만료 구분.
- 이관/복구: 원본 전체 byte 불변·관계/건수/버전대조·DB+파일 세대일치·실제 복원·새 운영 소스 인수.
- 검수: 논리적 변경별 별도 문맥 독립 검수와 findings 처리. 실제 배포/API/화면·보존을 확인한 경우에만 RELEASED.

설계 문서는 문법/링크/정합성 검사를 수행한다. 코드가 없는 이번 작업에 앱 전체 회귀를 실행한 것으로 보고하지 않는다. 실제 승인 정답/회사 근거가 없으면 실자료 검증은 계속 BLOCKED_EVIDENCE다.

## 4. 운영 문서에 반드시 확정할 것

환경별 설정/비밀 전달, DB migration/rollback 방식, 파일 volume/용량/접근권한, 백업 주기·보관기간·복원 측정, 서비스 시작/중지/health/알림·마스킹 로그, 의존성/SBOM/NOTICE, 사용자 발급·재발급 담당자, 제한 재시도/큐 동시성, 스케줄러 단일성·타임존, 사고/비밀번호 노출 대응을 기록한다.

## 5. 미정/차단 사항

실제 서버·도메인·TLS/내부 접근망·최종 조직/프로젝트 권한표·계정 발급 대상·메일/비밀 전달 경로·암호/세션 보안 수치·스토리지/백업 예산·AI 공급자/계약/비용은 미정이다. 이 결정 없이 합성 개발은 가능하지만 민감 자료 이전/원격 운영 활성화는 하지 않는다. 실제 입찰 제출/자동 투찰/외부 참여 확정은 계속 금지한다.
