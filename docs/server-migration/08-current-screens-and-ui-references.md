## 1. 설계가 어디까지 끝났는가

**기본 설계와 구현 순서가 준비됐지만 전체 상세 설계 완료는 아니다.** 별도 Astra 검수 GO도 해당 설계 초안의 차단 지적 해소를 뜻하며, 모든 화면 확정·구현·보안 검증·배포 승인을 뜻하지 않는다.

| 영역 | 현재 상태 | 남은 내용/확정 시점 |
|---|---|---|
| 스택·기본 구조 | 방향 확정 | SM02에서 지원 버전·호환성·라이선스 고정 |
| 인증 | DB 계정·SSO 제외·첫 암호 변경 서버 강제 계약 작성 | SM03 전 역할/객체 권한표, 암호·세션 수치, 계정 발급/복구 수단 |
| 화면 | S01~S16 목적·동선·오류 상태 초안 | SM02/03 및 SM06의 해당 화면별 시안·필드·입력 규칙·반응형 인수 |
| 데이터/작업 | 논리 엔터티·버전·이관·outbox 원칙 작성 | SM04/05에서 실제 스키마·인덱스·상태 전이·예약 주체·작업 제한 |
| 운영 | 단계와 백업/복구 게이트 작성 | SM07/08 전 서버·접근망·TLS·비밀·백업 위치/주기·복구 목표 |
| 실자료 검증 | 기존 근거 부족 상태 유지 | 사람이 승인한 최신 정답/회사 증빙 없으면 NOT_EVALUATED/BLOCKED_EVIDENCE |

합성 데이터로 SM02 개발 골격을 시작할 수 있는 수준이다. 미래 모든 화면의 설계를 먼저 끝내기 위해 구현을 무기한 미루지 않고, 카드별 필요한 상세를 구현 전에 확정한다. 민감 자료 이전과 운영 활성화에는 해당 미정 사항의 해소가 필요하다.

## 2. 현재 화면과 목표 화면 대응

현재 로컬 제품 진입점은 `/decision-preview`다. 서버가 [HTML](../../frontend/public/bid-decision-dashboard-preview.html)과 [실제 데이터 연결 JS](../../frontend/public/dashboard-live.js)를 제공한다. 단독 HTML 실행과 localhost API 연결 상태를 혼동하지 않는다. 아래는 **소스에 연결 코드가 존재함**을 확인한 목록이며 이번 시점의 운영 성공/데이터 최신성을 보증하지 않는다.

## 3. 공개 GitHub 후보 비교

아래는 공식 저장소 README와 공식 문서를 읽은 **선정 제안**이다. 최신 브랜치를 제품 의존성으로 고정한 것이 아니며 설치 시 선택 버전·LICENSE/NOTICE·하위 의존성·보안 공지를 재확인한다. 비교는 제품 요구에 대한 판단이며 벤치마크/실제 사용성 테스트 결과가 아니다.

|---|---|---|
| [shadcn-ui/ui](https://github.com/shadcn-ui/ui) | 수정 가능한 UI 컴포넌트, 메뉴·탭·다이얼로그·폼·시트 | **우선 후보**. [공식 Vite 안내](https://ui.shadcn.com/docs/installation/vite)가 있다. 가져온 소스의 유지보수·업데이트 책임과 Tailwind 도입 범위를 확인. 완성 앱/인증 제공 제품은 아님 |

## 4. 권장 조합과 화면 적용

**제안: React/Vite + shadcn/ui + 필요한 목록의 TanStack Table, PDF 원본 대조에는 PDF.js.** 관리자 예제에서는 배치만 참고한다. 이 제안은 사용자 UI 승인 또는 설치 결정이 아니며 기존 02의 컴포넌트 라이브러리 미정 상태를 자동 변경하지 않는다.

- 공통 틀: PC는 좌측 메뉴/상단 현재 위치, 모바일은 접히는 메뉴. '검토할 일·공고·문서·판단'을 업무 중심으로 묶고 계정/수집 설정은 권한에 맞게 분리한다.
- S04/S08: 공고명·기관·기한·상태·문서 위험·다음 행동을 우선 표시. 390px는 중요 필드 카드와 상세 진입, 1440px는 비교 가능한 표. 미확인 값을 0/정상으로 표시하지 않는다.
- S05/S09: 원본과 추출/정답 편집을 나란히, 모바일은 전환/세로 배치. 페이지·표 위치와 근거 부족 이유를 먼저 보여주고 SHA는 상세 펼치기에 둔다.
- PDF.js 사용 시 권한 검사된 동일 origin 원본 API와 제한된 파일 크기/페이지/자원 정책을 연결한다. 공개 데모 뷰어/CDN에 원문을 보내지 않으며 권한 취소·캐시·미지원 형식·뷰어 오류를 별도 검증한다.
- S01/S02/S14: 외부 템플릿 로그인은 레이아웃만 참고. Django 세션·CSRF·첫 변경 강제/재로그인·초기 암호 발급/폐기 계약을 적용한다.
- S03: 장식용 차트보다 지금 확인할 공고, 원본 부족, 수집 실패와 마지막 성공시각을 우선한다. 근거 없는 예상 수익·성공률 차트를 만들지 않는다.

## 5. 다음 구현 전 확정할 상세

첫 화면 검증 묶음은 로그인/암호 변경, 공고 목록, 공고 상세, 원본·정답 비교다. 합성 자료로 390px/1440px 시안을 먼저 확인하고 역할/비밀 경계를 보존하면서 API에 연결한다.

각 화면 카드에 필드/필수값/검증 메시지, 정렬·필터·페이지 URL, API 요청/응답/권한, 로딩·빈값·오류·세션만료·충돌 입력 보존, 키보드/초점/레이블, 모바일 행동, 완료 증거를 연결한다. 라이브러리 접근성 표방만으로 한국어 화면 접근성 통과를 주장하지 않는다.

후보를 모두 설치하거나 새로운 인증/라우터/배포 서비스를 추가하지 않는다. UI 선정과 함께 필요한 컴포넌트만 검증된 버전으로 도입하고, 다른 기능/기존 데이터는 그대로 보존한다.
