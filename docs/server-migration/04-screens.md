# 04. 화면별 설계와 사용자 흐름

[전체 목차](README.md)

## 1. 공통 구조

아래는 목표 화면 설계이며 구현/사용자 UI 승인 완료가 아니다. 기존 운영 자산 `/decision-preview`의 목록·상세·후보·수집·판단/영향인자·이력과 BID06 검수를 유지하면서 재구성한다. 관리자 사이트는 계정/기준정보 관리에만 쓰며 전체 사용자 업무 화면을 대체하지 않는다.

공통 상태: 로딩, 빈 데이터, 권한 없음, 세션 만료, 암호 변경 필요, 요청 실패, 오래된 원본, 저장 충돌을 구분한다. HTTP 실패를 0건으로 표시하지 않는다. URL에 필터/페이지를 보존하고 데스크톱1440/모바일390에서 가로 넘침·키보드·레이블을 확인한다. SHA/내부 ID는 기본 목록 대신 펼치기에 둔다.

## 3. 주요 사용자 흐름

- 신규 계정: S01 → S02 → 재로그인 → S03. S04를 직접 열거나 API를 호출해도 변경 게이트를 통과해야 한다.
- 공고 검토: S04/S06 → S05 → S08 문서 보완 → S09 독립 정답 검수 → S10 회사 증빙 대조 → S12 사람 판단.
- 운영: S07 일정/수동 수집 → S13 작업 관측 → 실패 단계별 원인 확인 → 권한·한도 안에서 명시 재시도.
- 관리: 변경 완료 관리자 → S14 계정 발급/재발급 → S16 감사 확인. 실제 임시 암호를 감사 화면에 남기지 않는다.

## 4. 핵심 화면 상세

S05: 왼쪽/상단은 공식 원본 사실·버전·시점, 오른쪽/하단은 규칙/AI 해석과 검수 상태. 원본 미확보/STALE/취소 상태를 항상 보이게 한다. 외부 공식 링크는 사용자가 명시 클릭할 때만 연다.

S09: 데스크톱에서는 원본 뷰어와 추출/독립 정답 편집을 비교하고 모바일에서는 세로로 제공한다. 서버 파일은 로그인·문서 권한을 확인한 전용 전달 API로 열며 무인증 정적 경로를 만들지 않는다. 지원되지 않는 원본 형식은 승인된 로컬 뷰어 안내와 원본 식별/위치 입력을 제공한다. 전체 페이지/표/각주/이미지/OCR 상태는 불명과 해당 없음, 검토 완료를 구분한다. 대표성 확인 전 전체 정확도로 일반화하지 않는다.

S07/S13: 일정을 저장하는 것과 실제 수집 성공을 구분한다. 마지막 성공시각·최근 오류·조회 기간·건수·소스 최신성을 함께 보여준다. 실행 버튼 중복 클릭은 같은 작업으로 연결하고 클라이언트 timeout을 서버 실패/취소 완료로 오인하지 않는다.

S10/S12: 회사 증빙 누락은 입력할 다음 자료와 담당자 확인 필요를 표시한다. 기술/인력 보완 시 비용·허용 조건·기간을 함께 검토하고 법적 필수 자격은 비용이나 기대 수익으로 우회하지 않는다.
