총액 자체도 회사 기밀일 수 있다. 원가 입력 승인 권한과 조회용 가공 결과를 분리하되 일반 사용자와 직책자에게 제공되는 **승인된 공통 사업 분석 결과**는 동일하게 한다. 모든 사용자란 인증·초기 암호 변경 완료 및 사업부 접근 승인된 사용자이며 인터넷/타 부서 공개가 아니다.

## 2. 원가 기준과 결정적 계산

입력은 사업부 기준 기간, 통화(KRW), 총인건비(급여·고용주 부담·퇴직급여·복리후생비 중 포함 범위를 명시), 총 MM 또는 합의된 배부 기준 MM, 가용 MM, 기준 확인일/유효기간, 출처의 비민감 참조, 원가 구성/배부 방식이다. 총인원과 전체 기준 MM은 인건비 집계와 같은 기간·범위에 맞춘다. 직급/직무별 단가 및 개인 급여 입력은 제공하지 않는다.

- 평균 MM 원가 = 사업부 기간 총인건비 / 같은 기간의 배부 기준 MM.
- 최초 단순 기준 후보: 총 기준 MM(평균 FTE × 기간 월수). 가용 MM 또는 생산 MM으로 배부하는 경우 별도 기준 방식으로 승인하며 총 MM과 혼용하지 않는다. 인원/기간/가동률 가정과 기준을 명시하고 회사가 선택하기 전 원가율은 확정 수치가 아니다.
- 사업 예상 인건비 = 해당 사업 필요 MM × 승인 평균 MM 원가.
- 사업 예상 총원가 = 예상 인건비 + 외주/직접경비/인프라/기타 비용 + 미포함 간접비·위험충당금(중복 계산 금지).
- 사업 예상 이익 = VAT 제외 예상 공급가액 - 예상 총원가.
- 예상 이익률 = 예상 이익 / VAT 제외 예상 공급가액 × 100. 공급가액 0 또는 미확정이면 이익률은 null. 실제 회계상 영업이익/수주확률과 구분한다.

금액은 정수 원 또는 Decimal, MM은 합의된 Decimal 정밀도를 사용하며 서버 산식을 정본으로 한다. 0 이하 분모, 음수 비용, 기간 불일치, 미승인/만료 기준은 검증 오류 또는 UNVERIFIED로 처리한다. 가용 MM이 부족해도 보완 비용·기간·위험을 평가하고 법적 필수 조건은 우회하지 않는다. 근거 없이 0원/가짜 마진/AI 수주 확률을 생성하지 않는다. 사용자 가정 시뮬레이션은 승인 견적이나 과거 의사결정 이력을 덮지 않는다.

## 3. 역할과 업무 범위

| 기능 | 승인된 사업부 사용자 | 지정 업무 승인자 | 시스템 관리자 |
|---|---|---|---|
| 안전한 공고/추천/사업별 예상 수익성 조회 | 허용 | 허용 | 별도 업무 권한 있을 때만 |
| 필요 MM·비용 가정 시뮬레이션, 공통 의견 작성 | 허용 | 허용 | 별도 업무 권한 있을 때만 |
| 사업부 집계 기준 작성·승인·변경 | 불허 | 지정 권한 | 기본 불허 |
| 최종 Bid/No-Bid 확정 및 변경 이력 | 조회 | 결정 권한 | 기본 불허 |
| 계정/서비스 관리 | 불허 | 별도 운영 권한 | 허용 |
| 개인 작업 원장/비공개 객체/비밀 | 기존 범위만 | 기존 범위만 | 기본 우회 없음 |

역할명과 승인자 지정은 회사 정책/책임자 확인 후 매핑한다. 권한은 DB와 서버 범위에서 검증한다. 기술 superuser·관리자·직책명만으로 업무 권한을 자동 부여하지 않는다. 공유된 결과를 읽는 기능과 원본 작업/재시도/취소 권한은 다르다. PR #5의 owner-scoped 작업 권한을 풀지 않는다. 읽기 전용 사용자/개별 검수 권한 등 추가 요구는 승인 후 적용한다.

## 4. 재식별 방지

사업부 단위의 합계도 인원 1명 또는 소규모일 때는 개인 급여가 될 수 있다. 원가의 직급/직무/개인 필터, 임의 기간·부분집합 비교, 과거 버전·CSV/export의 차분, 그룹 별 단가와 MM/손익의 역산, 반복 가정 조회 조합을 통해 특정인의 원가를 유추할 수 없도록 정책을 설계한다. 승인된 비용 기준은 충분히 큰 단위·고정 기간으로 제공하고 소규모 그룹 및 인원변동 전후의 정밀 수치는 비노출/상위 집계/구간화한다. 공개 기준 단위와 동일한 정밀도로 파생 결과와 export를 계산하거나 더 큰 구간으로 제한하여 숨긴 정밀 기준이 파생 이익으로 노출되지 않게 한다. 비용/이익·평균 MM·인원/기간의 조합을 함께 점검한다. 기본은 안전성 확인 전 정밀 총액/소그룹 비노출. 최소 집계 인원수·기간·반올림 단위·보존기간·열람 범위는 회사 승인을 받아 설정하고 안전하지 않은 경우 FAIL_CLOSED로 처리한다. 집계라고 완전 익명화되었다고 주장하지 않는다.

입력 API는 허용된 필드만 수락한다. 자유 입력/첨부를 통해 원가 원본을 우회 저장하지 못하도록 원가 입력 기능에는 급여 파일 업로드·자유 개인정보 기입란을 제공하지 않는다. 타 업무 첨부/의견은 별도 정책과 마스킹 적용. 로그, 에러, 백업·검색·export·프롬프트에도 동일한 경계를 적용한다. 외부 LLM 자동 전송 금지이며 회사 정책/승인 없는 원가·비공개 자료 전송은 별도 금지다.

## 5. DB/API/UI 계약 (구현 후보)

DepartmentCostBasis/Version: 사업부 ID, 기준 기간, 총인건비, 배부 기준 MM/방식, 집계 가용량, 포함 항목/통화, 출처 참조 및 승인 상태, 승인자/확인일/만료일, revision. 개인 급여나 개인 단가 컬럼 없음. 동일 기간 활성 기준 version의 유일성과 값 범위를 DB 제약으로 보완한다. 사업별 BidCostEstimate는 notice_version, cost_basis_version, 필요 MM, 예상 공급가액, 기타 비용 가정, 계산 버전, 승인/검증 상태를 기록한다. 기존 승인 견적/결정은 변경하지 않고 새 기준으로 재평가 시 새 revision을 생성한다. 저장용 승인 기준과 승인된 공개 projection을 분리한다.

읽기 API 후보: 공통 집계 기준 projection, 사업별 수익성 projection/의견. 쓰기 API 후보: 집계 기준 변경(승인 정책/expected_revision/감사), 견적 시뮬레이션/의견, 최종 명시 결정. 권한·부서 범위·CSRF·입력 validation·동시성·안전 오류를 서버에서 적용한다. 정확한 URL과 기존 OpenAPI 계약, 마이그레이션은 AGG-01에서 확정한다. UI는 S10 집계 기준 및 역량, S12 사업 원가/이익·의견·결정 화면으로 연결하되 사용자별 가정과 승인된 기준을 구분한다. 읽기 작업은 외부 I/O 또는 워커 실행을 유발하지 않는다.

## 6. 인수와 시범 운영

AGG-01~05 순서: 기준/역할 설계 → 집계 모델/계산 → 공통 화면 및 권한 → 음성/회귀/독립 검수 → 승인된 격리 사내 시범 운영. 기존 PR #5의 보안 검수·동일 HEAD CI·원본 불변성·rollback 게이트 후 진행한다. 테스트는 합성 데이터만 사용하며 개인 급여 입력 거부, 사용자간/타 부서 접근, 승인자 변경 및 concurrency, 0분모/VAT/소수/이력, 누락 기준, 소그룹/차분·역산/API/export/로그 비노출을 포함한다. 기존 자료의 개인 식별 원가를 마이그레이션하지 않고 회사 승인 원천에서 산출한 집계만 별도로 검증 후 입력한다. 원본·기존 백업을 삭제/수정하지 않는다.

시범 환경은 별도 승인된 사내 서버에서 독립 DB/스토리지/서비스 계정/HTTPS/백업·복구를 확인한 뒤 사용자를 발급한다. 운영 환경/내부 주소/계정은 공개 저장소에 기록하지 않는다. 공고/RFP 분석·추천·공동 검토·예상 수익성·의사결정을 우선 제공하고 제안서 자동 생성/출력은 후순위 후보로 둔다. 이 문서는 설치/실자료 처리/운영 권한 변경 승인이나 완료 증거가 아니다. 실제 입찰 제출·외부 공개는 금지 상태 유지.
