# 입찰공고부터 제출·수주·평가 결과까지 관리: 기능 조사

- 조사일: 2026-10-09
- 단계: 사용자 화면 설계 입력(리서치). 실제 공공 API 인증·응답·자동 수집·회사정보 연동은 아직 검증하지 않았음.
- 입력 요구: 공고 확인 후 실제 제출 여부, 수주 여부, 평가점수 등의 관리와 기업들의 실무 방식을 반영한 UI 퍼블리싱.

## 공식 데이터 출처와 제약

| 영역 | 공식 시스템/데이터 | 설계상 주의 |
|---|---|---|
| 공고 조회 | 조달청 나라장터 입찰공고정보서비스 | 공고 변경이력·업무구분과 첨부를 확인해야 한다 |
| 개찰·낙찰 | 조달청 나라장터 낙찰정보서비스 | 개찰결과·최종낙찰자·순위·유찰/재입찰 등 공개범위. 누락=탈락은 아님 |
| 계약 | 조달청 나라장터 계약정보서비스 | 계약결과/변경을 공고와 연결하되 매칭 모호성을 보존 |
| 공고→계약 전체 | 조달청 나라장터 계약과정통합공개서비스 | 번호별 공개 가능한 진행 단계. 과정 일부가 없는 공고가 존재함 |
| **우리 업체가 제출했는지** | 나라장터 이용기관/조달업체 계정의 제출내역, 접수증, 담당자 확인 | 공개 낙찰 API로 자동 확정 불가. 적절한 인증과 공식 제공 여부 별도 검증 |
| **기술평가 점수** | 공고별 공개된 제안서 평가결과, 기관 공식 자료, 업체 통보 | 모든 업체·공고의 점수 공개 보장 없음. 비공개=0점 금지 |

## 다른 기업 및 상용 서비스의 업무 관리

현재 상용 제품의 제품 소개와 공개 자료에서 확인되는 일반적인 운영 패턴:

1. **기회 발굴/탐색:** 공고번호, 기관, 요구기술, 기한과 담당자를 CRM/RFP tracker에 등록
2. **Bid / No-Bid:** 자격·기술·인력·수익성·일정으로 참여 여부를 판단하고 비참여 사유도 기록
3. **제안서 제작:** 담당자 할당, 과업·서류별 대응/완료 체크리스트, 수정/승인, 내부 검토 일정 관리
4. **제출:** 제출 일시, 담당자, 접수 완료의 증빙 또는 접수 확인 여부를 기록
5. **선정 및 계약:** 개찰, 우선협상, 낙찰, 계약 체결을 별개의 상태로 보존
6. **Win / Loss 및 회고:** 기술·가격 점수, 점수 미공개 여부, 낙찰업체, 실패사유, 다음 입찰 개선항목
7. **성과지표:** 참여→제출→선정 전환율, 수주율, 미참여 사유, 공고 분야·기관별 경향(확인된 자료만)

## 추천 데이터 구조(아직 설계안)

- `Notice`: 공고번호+차수+업무유형+관측시점/원문 출처(공개 정보)
- `Pursuit`: tenant/company, 공고참조, 참여 결정, 사유, 담당자, 단계, 내부 기한(비공개)
- `SubmissionRecord`: 회사/공고, 제출 상태(`UNKNOWN`, `SELF_REPORTED`, `RECEIPT_SIGHTED`, `SOURCE_VERIFIED`), 증빙 출처/확인자/시간(민감 정보 분리)
- `Outcome`: 공고 단위 낙찰/개찰 상태와 **회사 단위 우리 업체 선정/미선정 판정**은 서로 다른 기록
- `EvaluationScore`: 기술/가격/총점의 값+만점+공식/기관 통보/내부 근거+비공개/미확인 상태
- `ReviewNote`: Bid/No Bid 사유·미선정 사유·개선항목·연결된 출처

숫자 `0`과 `UNKNOWN`은 다르다. 상태 자체와 출처·관측시점·입력자·검증여부를 각각 추적한다.

## 데이터 보안 및 서비스 제약

- 실제 업체의 입찰가·제안서·담당자/연락처·내부 평가 결과는 공용 목록/공개 GitHub로 공개하지 않는다.
- 회사 소유 입찰 기록 접근은 인증된 tenant 소유권과 객체 수준 권한 확인 후만 허용한다.
- 공공 오픈API는 읽기 전용 사용하되, 업무구분별 URL/요청조건·키·요청한도·이용조건은 실제 API 계약을 확인한다.
- 제안서 제출 자체를 서비스에서 자동 수행하거나 타인의 세션·인증수단을 재사용하지 않는다.
- 장기 프로젝트에서 source verification workflow를 개발하기 전에는 공개 개찰 결과가 존재해도 업체 개별 제출 여부를 `SOURCE_VERIFIED`로 승격하지 않는다.

## 이번 퍼블리싱 범위

- `frontend/public/ui-review.html`: 합성 목록
- `frontend/public/bid-detail-review.html`: 상세·자격·RFP·제출·결과·이력 6개 탭
- 화면 입력은 JavaScript 메모리로만 보존한다. 탭 이동/새로고침 시 초기화되며 DB/API에 저장하지 않는다.
- 사용자의 화면 검토 이후 수용할 화면과 상태·데이터 계약을 확정한다.
