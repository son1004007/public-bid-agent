# 단계별 AI 실행 카드

이 문서는 [제품 검토](../reviews/PRODUCT_REVIEW_AND_RESTART_PLAN_2026-10-30.md)를 실제 작업 단위로 나눈 **제안 백로그**다. [AI 시작점](AI_START_HERE.md)을 먼저 읽는다. 기존 [BID 실행 계약](DEPARTMENT_BID_NOW_EXECUTION_2026-10-18.md)과 승인 범위를 유지하며, 작업 카드 작성은 실행 승인이나 완료가 아니다.

한 번에 한 카드만 수행한다. 실제 자료가 없는 카드의 선행조건을 합성 데이터로 대신 충족했다고 쓰지 않는다. 아래는 작업 위치의 시작점이며 최신 파일/호출 관계에 맞게 조정하고 이유를 기록한다.

## 공통 종료 규칙

- 코드/API/저장 계약 변경: 관련 설계·테스트·README 동기화, 해당 회귀/필수 CI, 독립 Codex GO, 정확 SHA 근거가 필요하다. 테스트 개수 자체를 성능 근거로 쓰지 않는다.
- 실자료 카드: 사용 권한·최신 원본·범위·검수 주체·미확인 영역을 기록한다. 외부 전송·공개 Git에 민감 자료를 넣지 않는다.
- UI 카드: 합성 시안/사용자 검토와 코드 검수를 구분한다. 실제 브라우저 390px/1440px 정상·빈 결과·오류·경합을 확인한다.
- 운영 인수: 사용자 권한·고정 소스·기존 데이터 백업/검증·복구 경로를 확인한다. 문서/코드 게시와 운영 배포는 다르다.
- 완료 증거가 부족하면 `IMPLEMENTED_UNVERIFIED`, `BLOCKED_EVIDENCE`, `NOT RUN`으로 남기며 다음 BID의 선행조건을 자동 해제하지 않는다.

## A01 · 날짜 의존 회귀 테스트 정비

**왜:** 최신 main CI가 테스트의 고정 마감일 때문에 실패해 후속 감사/backend 검사가 skipped 됐다. 운영 마감 정책을 바꿀 문제가 아니다.

- 읽기: 제품 검토 F-01, `local_app/test_procurement_filter.py`, `dashboard_backend.normalize`, `procurement_filter.bid_window/apply`, `.github/workflows/sprint1-ci.yml`.
- 시작: `PYTHONPATH=local_app python -m unittest test_procurement_filter.DepartmentClassificationTests.test_title_without_technical_words_but_official_taxonomy_sw -v`로 기준 실패 확인.
- 작업: 테스트 관측 시각 고정. 기존 `at` 경로를 재사용하거나 normalize에 호환되는 clock 주입. 현재 날짜에 맞춰 fixture 마감만 미루지 않는다.
- 검증: 마감 전·정각·후, KST/UTC 경계, 취소 우선, 등록기한 불명. 미래/과거 관측시각에서도 동일한 기대 결과. 관련 테스트 후 Python 3.12 지원 환경의 필수 전체 CI를 실행한다.
- 완료: 기존 실패 해결, 테스트 삭제/skip/운영 정책 완화 없음, 후속 감사/backend 검사 실행과 결과 확인, 독립 GO 및 같은 SHA CI success. 새 실패는 별도로 진단.
- 산출물: 작은 수정 커밋/PR, 검증 기록, CURRENT_STATE/TASKS의 현재 실패 상태 갱신.
- 다음: A02. 실자료 없으면 필요한 원본·검수 역할·재개 조건 기록; A07 합성 준비 가능 여부 검토.

## A02 · 최신 원본과 독립 정답 파일럿 확보

**왜:** 현재 도구가 평가할 실제 독립 정답이 없다(마지막 운영 기록 기준). 추출 결과를 정답으로 쓰면 누락을 발견할 수 없다.

- 읽기: `docs/design/BID06_GROUND_TRUTH_2026-10-19.md`, 제품 검토 6절, `rfp_ground_truth.py`, `rfp-ground-truth.js`, `rfp_original_workflow.py`.
- 입력: 사용 권한 있는 최신 공식 공고/첨부, 차수/정정·취소·SHA, 사람 검수자. 회사 자료는 아직 불필요.
- 작업: 먼저 1~2개 공고에서 라벨 기준을 맞춘다. 원본의 참가자격/평가/과업 구절·페이지/표/각주/OCR 위치를 후보와 독립적으로 검수한다. 명시 승인 전에 전체 선택 범위와 문서 최신성을 확인한다. 5~10개 파일럿 확대는 제안이며 대표성 보장이 아니다.
- 검증: 새 차수·SHA 변경·취소·중복/겹친 범위·보류·미검수 경로가 승인 평가로 잘못 포함되지 않는지 기존 도구에서 확인한다. 후보 밖 누락 구절도 기록한다.
- 완료: 선정 이유·검수 범위·문서 결속·가명 검수자 참조·판단 불일치 처리·미확인 영역을 로컬에 남기고 사람이 실제 승인한 정답 확보. 정답 파일/원문을 GitHub에 복사하지 않는다.
- 차단: 사람이 검수하지 못하면 `BLOCKED_EVIDENCE`. AI가 검수자의 승인을 대신하지 않는다.

## A03 · 범위 한정 평가와 누락 원인 개선

**왜:** 수치만 높이는 것이 아니라 중요한 요건이 왜 빠지는지 알아야 한다.

- 읽기: `rfp_ground_truth.evaluate/_counts`, `rfp_requirements.structure`와 상한 상수, `test_rfp_ground_truth.py`, 기존 BID-06 검증 보고.
- 작업: 튜닝용/holdout을 구분해 범주·경로별 TP/FP/FN·분모와 Precision/Recall/F1/누락률을 계산. 문구 정확 일치/의미 검토를 분리하고 분절·오분류·추출실패·상한·실제 누락을 분류한다.
- 수정 범위: 실패 사례가 입증한 추출/표시/검수 경계 하나씩. 전체를 새 모델/RAG로 교체하지 않는다. 상한을 변경하면 자원/응답/누락 안내 계약도 검증한다.
- 검증: null 분모, 과거 차수 무효화, 승인 없는 평가 금지, 학습 사례를 holdout으로 재사용하지 않음, 새 합성 회귀와 원본 재검토. 원본이 바뀌면 기존 수치를 최신처럼 유지하지 않는다.
- 완료: 평가 소스 버전·표본 분포·실측·오류 사례·비교 가능한 baseline·미확인 영역을 보고하고 독립 검증. 허용 품질과 범위의 책임자 결정 기록 후 **그 범위의** BID-06 VALIDATION_DONE 판단. 전체 문서 대표성을 자동 주장하지 않는다.
- 산출물: 비식별 평가 보고와 필요한 작은 수정/회귀. 민감 사례/정답 원문은 로컬 보존.
- 다음: 조건 충족 시 A04, 미충족이면 같은 실패 유형의 작은 보완 또는 증거 대기.

## A04 · 요건과 회사 증빙 비교 (BID-07 첫 수직 기능)

**왜:** 자료가 있다는 사실과 특정 공고의 참가조건을 충족한다는 사실은 다르다.

- 읽기: D-20, BID-07 카드, `bid_readiness.py`, `operations.py`의 registers, `rfp_requirements.py`, 현재 API/저장 트랜잭션 계약.
- 선행: BID-07 착수 범위 확인, 최신 RFP와 승인된 회사 증빙·확인 책임자. 실제 자료는 회사 허용 환경에서만 처리.
- 작업: 공고 1건/필수요건 한 묶음부터 조건의 AND/OR·예외·기한을 원문에 연결하고 증빙 참조·유효기간·확인일·확인 주체와 대조한다. 상태는 충족/불충족/미확인 및 보류 사유로 구분한다. 인력 부족은 보완 검토로 남기고 법적 필수요건과 혼동하지 않는다.
- 설계: 새 저장 계약이 필요하면 revision/잠금/원자성·이전 기록 보존·민감 응답 제한을 먼저 정의하고 독립 설계 검수한다. 기존 자료 준비도 상태를 일괄 충족으로 승격하지 않는다.
- 검증: 누락·만료·서로 상충하는 증빙·차수 변경·동시 저장·회사 프로필 변경·겸임/협력 적용 예외. 원문 사실과 사람이 확인한 결과의 구분 확인.
- 완료: 하나의 공고를 근거까지 추적 가능, 미확인이 통과하지 않음, 구버전 이력 보존·재검토 표시, 관련 API/UI/합성 회귀와 독립 검수. 이 단계만으로 READY_TO_BID_VERIFIED는 아님.
- 다음: A05.

## A05 · 기간별 인력과 보완 후 사업성 (BID-07 완성)

**왜:** 지금 기술/인력이 부족하더라도 합법적인 보완 후 이익이 남을 수 있다. 반대로 예산이 커도 비용·일정이 맞지 않으면 참여 근거가 약하다.

- 읽기: `operations.calculate/clean_plan`, `workforce.py`, `staffing_requirements.py`, `bid_readiness.py`, 관련 테스트와 제품 검토 7절.
- 작업: 기존 계산기를 재사용해 사업기간별 역할/MM·가용성·겸임과 내부 인건비·외주/채용·간접비·제안비·예비비를 연결한다. 공동수급/하도급 허용과 협력 비용은 해당 공고 근거를 확인한다. 공급가액/VAT 기준과 현금흐름 가정을 명시한다.
- UI: 보수/기준/낙관 시나리오의 가정·근거·불확실성을 보여준다. 예산을 예상 수주금액으로 대체하지 않으며 입력 없는 비용은 미확인이다.
- 검증: 가용 0과 미입력 구분, 일정 중복, 단가/원가 revision 변경 시 stale, 부분 비용 누락, VAT/반올림/마진 분모0, 큰 예상 이익으로 필수 자격을 우회하지 못함.
- 완료: A04와 합쳐 1공고의 증빙/인력/사업성/제안서 부족 항목을 책임자가 확인 가능하고 계산 재현·변경 무효화 검증. 마진 임계치는 사용자 정책 없이 임의 확정하지 않는다.
- 다음: A06. BID-07 완료 판단은 실제 증빙·독립 검수와 기존 BID 계약 전체 충족 여부로 기록한다.

## A06 · 한 공고의 검토와 사람 결정 UX (BID-08)

**왜:** 사용자가 여러 상태 화면을 해석하는 대신 다음 행동과 판단 근거를 한 흐름에서 확인해야 한다.

- 읽기: `frontend/public/dashboard-live.js`, `rfp-ground-truth.js`, 기존 상세/결정 API, `decision_support.py`, `bid_outcomes.py`, UI 검토 가이드.
- 시안: 합성 공고로 제목·발주기관·확인 기한→필수조건/미확인→사업성 시나리오→다음 행동 하나→참여/보류/불참 사유. 내부 SHA/상태 코드는 상세로 접고 원문 근거는 쉽게 연다.
- 연결: 사용자 시안 검토 후 같은 snapshot/revision의 기존 목록·상세 API를 사용한다. 비식별 큐 API에 민감 데이터를 추가하지 않는다. 결정과 참조 증거 버전을 저장하고 과거 결정을 보존한다.
- 검증: 390/1440px, 키보드, loading/empty/error, 늦은 응답·revision 충돌·정정 후 재검토, 저장/재조회. 미확인 근거가 있으면 준비 완료 상태 금지. 사용자 UI 승인과 Codex 코드 GO를 각각 기록.
- 완료: 대표 공고 하나에서 원문 확인부터 이유 있는 사람 결정까지 완주하고 저장 이력 재현. `READY_TO_BID_VERIFIED`의 확인 정책/책임자·근거 충족. 실제 입찰 제출은 하지 않는다.
- 다음: A07 최종 인수.

## A07 · 배포 패키지 완전성과 Windows 인수 (BID-09)

**왜:** checkout에서 성공해도 사용자에게 주는 패키지에 모듈이 없으면 새 설치는 실패한다.

- 읽기: 제품 검토 F-02, `.github/workflows/sprint1-ci.yml`, `.github/workflows/windows-synthetic-acceptance.yml`, `docs/DEPENDENCIES_AND_LICENSES.md`, 기존 P09/배포·복원 기록.
- 준비 작업: manifest의 서버 의존 모듈·정적 자산·필수 설정 누락을 검사한다. `server.py` 직접 import만이 아니라 간접 의존과 파일 경로도 확인한다. 기존 패키지 도구가 있다면 재사용하고 새 병렬 도구를 만들지 않는다.
- 패키지 규칙: 사용자 데이터·RFP·키·캐시·환경 파일 제외, 제3자 NOTICE/라이선스 유지. 저장소 전체 무차별 압축 금지.
- 검증: 깨끗한 임시 폴더에서 **실제 생성 아티팩트만** 사용해 Python 3.12 설치 의존성→서버 시작→health/주요 정적 자산→합성 핵심 흐름→정상 종료. 개발 checkout의 PYTHONPATH가 누락을 가리지 않아야 한다.
- 최종 인수: A06 이후 Windows 합성/브라우저·백업/복원 계약을 검증한다. 운영 배포가 승인된 경우에만 정확 소스·프로세스·백업·전후 원본 무결성·복귀 경로를 확인하고 적용한다.
- 완료: 패키지 재현/CI/독립 검수/NOTICE와 해당 범위의 Windows 인수 증거. 준비 작업만 했으면 BID-09 DONE 아님. 인터넷 공개 서비스 승인은 별도다.
- 다음: A08.

## A08 · 실사용 피드백과 다음 우선순위

**왜:** 테스트 수나 추천 수보다 실제 검토 시간과 중요한 누락 감소가 제품 가치를 보여준다.

- 입력: 허용된 실사용 공고의 비식별 측정 기록. 실제 제출·수주 결과를 추정하지 않는다.
- 작업: 검토시간 중앙값/범위, 확인한 필수조건 분모와 누락, 보류 해소 시간, 정정 재검토 누락, 판단 근거 연결률을 측정한다. 이전/이후 표본 차이와 사람 검수 시간을 함께 기록한다.
- 완료: 측정 방법·baseline·개선/악화·한계를 보고하고 가장 큰 병목 **하나**를 다음 카드로 만든다. RAG/모델/아키텍처 변경은 그 병목과 비용·자료 전송 경계에 근거가 있을 때 제안한다.
- 다음: 새 사용자 요구/실측에 따라 정의. 자동화·모니터링을 임의 재가동하지 않는다.
