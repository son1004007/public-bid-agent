## 1. 실측 — 실제 공급자 CLI

읽기 전용 버전·로그인 상태 조회:
- 개인 Windows 노트북 Gateway SSH 비승격 세션: `codex-cli 0.166.0` 존재, `codex login status` exit=0; `Claude Code 2.1.50` 존재, `claude auth status` exit=1. **Claude 계정/요금제 부재 판정이 아니라 그 SSH 컨텍스트에서 인증을 사용할 수 없다는 뜻**.
- 연결된 NAS Gateway SSH 세션에서는 `codex`, `claude` 실행파일을 PATH에서 찾지 못함. 다른 셸·UID·컨테이너의 설치 여부는 아직 UNKNOWN.
- 회사 data1의 별도 `public-bid-agent` 승인된 workspace/runtime mapping은 확인되지 않았으므로 회사 IDC에 설치, 계정 로그인, 모델 실행하지 않음.

Codex **사용자 공식 CLI로 실제 모델 요청 1건**, 이어서 기존 thread의 **실제 resume 요청 1건**:
1. 새 작업 디렉터리(개인 노트북 임시 격리 경로), `--sandbox read-only`, `--skip-git-repo-check`, `--json`, 프롬프트는 stdin의 `-`로 전달. RFP/회사 실적은 전부 합성 텍스트. 요청 내용: 최근 3년 실적 2건 필수, 가상 회사 1건 → 근거 ID `E1`로 분석.
2. JSONL에 `thread.started`, `turn.started`, `item.completed(agent_message)`, `turn.completed` 확인. 최종 응답 `{"requirement_id":"R1","assessment":"NOT_MET","evidence_ids":["E1"],...}`. 네트워크 실제 추론 성공, CLI exit=0.
3. 다음 호출은 직전 요구사항 수치를 다시 제공하지 않고 첫 결과 기억을 요청. 이전과 **동일 session UUID가 재사용**되며 결과 `required_project_count=2`, `evidenced_project_count=1`, `prior_assessment=NOT_MET`. `turn.completed`, exit=0. **세션 ID/사용자별 인증정보/원본 대화·Gateway 인증 환경 상세는 공개 Git에 기록하지 않는다**.
4. 실패 대응 실측: Windows npm PowerShell `codex.ps1`에서 공백 포함 prompt를 직접 인수로 넘기면 분할돼 인수 오류 → `codex.cmd` + stdin으로 수정. 설치된 0.166.0에서 `codex exec resume --sandbox ...`는 잘못된 명령 위치 → `codex --sandbox read-only exec resume ...`로 확인. 실패 후 새 세션을 무조건 생성하지 않고 동일 ID로 복구.

**한계**: 이는 *개인 Windows 사용자 CLI* 실측. 공용 서버에 해당 사용자 인증정보가 설치·등록됐다는 뜻이 아니며, 상업용 서버·다중 계정·동시성/보안·실제 RFP 판단 품질을 증명하지 않는다. 테스트 자료만으로 정확도 통계 산출 금지.

## 3. 테스트·재현

- [AI Gateway core workflow](../../../.github/workflows/ai-gateway-core.yml)에서 provider 계획/근거 검증 및 Codex Adapter 테스트. 실제 모델 및 기밀 접근 0건. 단계별 PR 최신 SHA 기준 실행 기록을 확인해야 함.
- [server-foundation-ci](../../../.github/workflows/server-foundation-ci.yml)는 PostgreSQL/SQLite·Windows/Ubuntu에서 `tests` 전체와 migration check를 실행. 새로운 [Django tests](../../../server/tests/test_ai_gateway_django.py)는 사용자별 권한·로그인 상태·세션 유일성/비공개 UUID·API 쓰기 차단 테스트. 실제 운영 DB 이전 및 데이터 정정 없이 ephemeral CI만.
- 중간에 신규 다중-job YAML 워크플로의 실행 전 파싱 오류가 있었으나 **이전 검증된 core workflow로 복구**하고, 기존 server-foundation-ci를 통합 Django/DB CI로 재사용한다. 부정확한 RUN PASS 기록 금지.
- 공개 테스트의 세션 UUID는 **합성 UUID**로 대체했고, 운영/사용자별 실제 session ID를 현재 소스·문서에 사용하지 않는다.
