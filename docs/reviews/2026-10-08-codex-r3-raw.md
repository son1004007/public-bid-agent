## 2. 판정

### 설계 착수 판정: `READY_FOR_LIMITED_POC`

다음 범위로 제한한 비공개 PoC 구현은 시작할 수 있습니다.

- 사용 권한이 확인된 표본 또는 합성 fixture
- 읽기 전용 공고 조회
- PDF 한 종류와 공고 API 한 종류
- 통제된 문서만 처리
- LLM은 `disabled` 또는 명확히 표시된 deterministic fake
- 실제 사용자·민감 회사자료·공개 SSE·실제 AI 홍보 없음
- 아래 MAJOR 항목을 PoC 성공 조건에 포함

현재 설계에는 OIDC, 객체 권한, SSRF, 파서 격리, 근거 버전, 보수적 판정, worker lease, 삭제 저널 등 실질적인 보호 계약이 이미 존재합니다. 따라서 외부 미확정 사항만을 이유로 제한적 PoC까지 보류할 근거는 없습니다.

### 공개 서비스 판정: `HOLD`

- 공개 비-AI 서비스도 구현·테스트·배포 증거가 전혀 없습니다.
- 공개 AI 서비스는 여기에 더해 실제 허용된 상용 LLM 인증·사용량·비용 경로가 확정되지 않았습니다.
- `disabled` 비-AI fallback은 비용 요구를 준수하는 안전한 대안이지만, “실제 사용자용 상용 LLM 분석”이라는 최종 목표 달성으로 간주할 수 없습니다.
- 아래 MAJOR 설계 쟁점, 외부 사실 검증, 공개 출시 게이트를 닫기 전에는 공개 승인이 불가능합니다.

이번 정적 설계에서 즉시 전체 구조를 폐기해야 하는 `BLOCKER`는 찾지 않았습니다.

## 3. 발견사항

### PBA-R3-001 — MAJOR: “현재 유효한 공고” 선택과 마감 상태의 결정 규칙이 완결되지 않음

근거:

- `docs/adr/ADR-002-procurement-data-lifecycle.md:L0011-L0018`
- `docs/adr/ADR-002-procurement-data-lifecycle.md:L0029-L0038`
- `docs/adr/ADR-007-analysis-state-evaluation.md:L0027-L0034`
- `docs/02-architecture.md:L0053-L0063`

실패 경로:

1. 동일 공고의 정정본이 원본보다 늦게 또는 순서가 뒤바뀌어 수집됩니다.
2. `supersedes_revision_id`는 있지만 분기·순환·중복·상충 정정 중 어느 revision을 “현재본”으로 선택할지 불변조건이 없습니다.
3. 원천 상태가 `OPEN`이지만 확인된 마감시각은 이미 지난 경우의 우선순위도 명시되지 않았습니다.
4. 잘못 선택된 revision이 `CURRENT + OPEN`으로 projection되면 ADR-007의 `SUITABLE` 조건까지 도달할 수 있습니다.

최소 수정안:

- `EffectiveNoticeProjection` 계약을 추가합니다.
- 마지막으로 성공한 완전 동기화 범위, revision 순서, branch/cycle 처리, 중복 및 상충 시 `UNKNOWN` 규칙을 정의합니다.
- 확인된 현재시각이 `deadline_utc` 이후면 원천 `OPEN` 문자열만으로 접수 가능하다고 표시하지 않도록 합니다.
- `availability_status`, `submission_window_status`, `source_freshness`, `as_of/last_successful_complete_sync`를 구분하거나 명확한 우선순위를 둡니다.
- 판단 충돌 시 fail-closed로 `UNKNOWN/NEEDS_REVIEW` 처리합니다.

검증:

- 역순 수집, 중복 revision, branch/cycle, partial page, 상충 상태, 마감 직전·직후, 서버 시계 오차, 정정 후 OPEN/CLOSED/CANCELLED fixture
- upstream 실패 뒤 과거 캐시를 `CURRENT`로 표시하지 않는 contract test

### PBA-R3-002 — MAJOR: PDF “파싱 성공”과 “판정에 충분한 추출”이 구분되지 않음

근거:

- `docs/adr/ADR-003-evidence-retrieval.md:L0009-L0014`
- `docs/adr/ADR-006-document-ingestion-security.md:L0014-L0019`
- `docs/adr/ADR-007-analysis-state-evaluation.md:L0031-L0039`
- `docs/03-test-plan.md:L0028-L0043`

실패 경로:

1. 이미지 스캔 PDF 또는 표·특수폰트가 포함된 PDF에서 제목만 추출되고 파서는 성공을 반환합니다.
2. 필수 참가요건이 있는 페이지가 누락됐지만 `ParsedArtifact`에는 성공/실패와 checksum만 남습니다.
3. 추출된 요건 집합에 필수조건이 없으므로 판정 엔진이 “확인된 필수조건 충돌 없음”으로 진행할 수 있습니다.
4. 누락 범위가 명시적 `UNKNOWN`으로 전파되지 않으면 잘못된 `SUITABLE`이 가능합니다.

최소 수정안:

- `extraction_completeness = COMPLETE/PARTIAL/UNREADABLE/UNKNOWN` 같은 별도 상태를 둡니다.
- 원본 페이지 수, 처리 페이지 수, 텍스트 없는 페이지, 표/이미지 전용 페이지, 중단 원인과 추출 범위를 기록합니다.
- `COMPLETE`가 아니면 필수요건 포괄성 확인 없이 `SUITABLE`을 금지합니다.
- OCR을 지원하지 않는다면 스캔 문서를 명시적으로 `NEEDS_REVIEW` 처리합니다.

검증:

- 이미지 전용 PDF, 일부 페이지만 추출되는 PDF, 표 안의 필수조건, 깨진 폰트, 빈 텍스트, 페이지 제한에 걸린 문서
- 위 사례가 `SUITABLE`로 끝나면 출시 실패

### PBA-R3-003 — MAJOR: 이미 열린 SSE 연결의 권한 철회 계약이 없음

근거:

- `docs/adr/ADR-001-auth-session-ownership.md:L0034-L0045`
- `docs/adr/ADR-001-auth-session-ownership.md:L0047-L0052`
- `docs/02-architecture.md:L0043-L0047`
- `docs/03-test-plan.md:L0017-L0018`

실패 경로:

1. 사용자가 유효한 세션으로 SSE 연결을 엽니다.
2. 이후 로그아웃, 세션 만료, 계정 삭제 또는 run 접근 폐기가 발생합니다.
3. 문서는 최초 연결과 재연결 권한 검사는 요구하지만, 기존 연결의 지속적인 재검사나 강제 종료 방법은 정의하지 않습니다.
4. 연결이 계속 살아 있으면 폐기 후에도 개인 분석 이벤트를 받을 수 있습니다.

최소 수정안:

- SSE 연결 최대 수명과 heartbeat 시 세션·계정·run 소유권 재검사 주기를 정의합니다.
- 세션 generation 또는 계정 상태 version을 연결에 결합합니다.
- 로그아웃·계정 삭제 시 열린 연결을 종료하거나, 다음 이벤트 전 DB 상태 확인으로 전송을 차단합니다.
- 이벤트 payload 최소화와 terminal 이후 종료 규칙을 명시합니다.

검증:

- 열린 연결 상태에서 로그아웃, 절대/유휴 만료, 계정 `DELETING`, run 취소, 소유권 폐기
- 재연결하지 않아도 다음 이벤트가 전달되지 않는지 확인

### PBA-R3-004 — MAJOR: 악성 원문·모델 출력의 브라우저 렌더링 sink 계약이 없음

근거:

- `docs/adr/ADR-006-document-ingestion-security.md:L0019-L0019`
- `docs/adr/ADR-006-document-ingestion-security.md:L0029-L0036`
- `docs/adr/ADR-003-evidence-retrieval.md:L0038-L0040`
- `docs/05-coding-standards.md:L0125-L0143`

문서는 PDF 텍스트와 모델 출력을 비신뢰 데이터로 취급하고 있지만, 그 문자열을 React에서 어떻게 렌더링할지는 정하지 않았습니다.

실패 경로:

1. PDF passage 또는 모델 결과에 HTML, Markdown 링크, `javascript:` URL이나 이벤트 속성이 포함됩니다.
2. 근거 강조를 위해 구현자가 HTML/Markdown renderer 또는 `dangerouslySetInnerHTML`을 사용합니다.
3. 저장된 passage를 다른 사용자가 열 때 stored XSS 또는 악성 외부 링크가 실행됩니다.
4. 세션 쿠키는 HttpOnly여도 사용자 대신 상태 변경 요청, 화면 위조 또는 민감 결과 유출이 가능합니다.

최소 수정안:

- 기본 렌더링은 React text node로 한정합니다.
- HTML은 허용하지 않고, Markdown이 필요하면 고정 allowlist sanitizer를 사용합니다.
- 링크는 서버가 만든 `canonical_source_url`만 클릭 가능하게 하고 `javascript:`, `data:` 및 원문 내 임의 URL은 활성화하지 않습니다.
- CSP와 외부 링크 속성 정책을 배포 계약에 추가합니다.

검증:

- PDF·모델 출력·프로필에 script, SVG, event handler, malformed Markdown, `javascript:`/`data:` 링크 삽입
- DOM 실행, 임의 navigation 및 credentialed 요청이 발생하지 않는 브라우저 E2E

### PBA-R3-006 — MAJOR: Agent 예산이 완전한 단조 증가 ledger로 정의되지 않음

근거:

- `docs/adr/ADR-004-llm-auth-cost.md:L0020-L0034`
- `docs/adr/ADR-007-analysis-state-evaluation.md:L0068-L0080`
- `docs/03-test-plan.md:L0045-L0059`

실패 경로:

1. 요청 토큰 16,000 제한은 지키지만 모델 출력 토큰이 크게 증가합니다.
2. timeout, retry, worker lease 재획득으로 같은 provider 호출이 중복됩니다.
3. 질문 대기 24시간과 총 실행 180초가 active time인지 wall-clock인지 구현마다 다르게 해석됩니다.
4. 예약 사용량과 실제 provider 사용량이 원자적으로 보존되지 않으면 계획·비용 한도 또는 호출 제한을 초과할 수 있습니다.

- run별 영속 budget ledger를 둡니다.
- 입력·출력 토큰, 호출 시도 수, 재시도, 문서 바이트, active execution time, waiting time, provider quota/cost 단위를 구분합니다.
- 모든 시도는 실패·timeout 여부와 관계없이 예산에 단조 증가로 반영합니다.
- 호출 전 reservation, 응답 후 reconciliation, `max_output_tokens`, 늦은 응답의 결과 저장 거부를 정의합니다.
- 사용자/day 및 서비스 전체 상한이 정해지기 전 공개 AI 실행은 비활성 상태로 유지합니다.

검증:

- timeout 뒤 retry, lease 회수, 중복 callback, 과대 출력, usage 정보 누락, 질문 대기 후 resume, 취소 직후 과금 응답
- 재시작 후에도 이미 사용한 예산이 복원되는지 확인

### PBA-R3-007 — QUESTION: `SEMANTICALLY_REVIEWED`의 사람 검토자가 누구인지 불명확함

근거:

- `docs/adr/ADR-003-evidence-retrieval.md:L0032-L0038`
- `docs/adr/ADR-007-analysis-state-evaluation.md:L0027-L0039`

현재 문서는 검증 방법·검증자·시각을 기록하고 모델 self-check만으로 승격하지 않는다는 점은 잘 정의했습니다. 그러나 어떤 사용자가 어떤 권한과 책임으로 상태를 부여하는지는 미정입니다.

실제 영향:

- 서비스 운영 검토자가 없다면 복잡한 조항은 계속 `NEEDS_REVIEW`여야 합니다.
- 일반 사용자의 “확인”을 서비스의 의미 검증과 동일시하면 신뢰 수준이 과장될 수 있습니다.
- 이 결정은 보안 결함보다는 실제 사용자 가치와 제품 문구에 직접 영향을 줍니다.

최소 수정안:

- `USER_ACKNOWLEDGED`, `SERVICE_REVIEWED`, `DETERMINISTICALLY_VERIFIED`를 구분합니다.
- 승격 권한과 감사 기록을 서버에서 강제합니다.
- 운영 검토자가 없는 MVP에서는 사용자 확인을 공식 검증처럼 표시하지 않습니다.

검증:

- 모델, 일반 사용자, 다른 사용자, 운영 검토자의 상태 변경 권한 테스트
- 각 상태가 UI에서 서로 다른 신뢰 수준으로 표시되는지 확인

### PBA-R3-008 — MINOR: 계정 삭제 같은 고위험 작업의 최근 재인증 요구가 없음

근거:

- `docs/adr/ADR-001-auth-session-ownership.md:L0015-L0017`
- `docs/adr/ADR-001-auth-session-ownership.md:L0047-L0052`
- `docs/adr/ADR-008-profile-privacy.md:L0034-L0042`

실패 경로:

- 8시간 절대 수명의 기존 세션이 탈취되거나 방치된 환경에서 사용되면 CSRF 검사를 통과하는 공격자가 계정 삭제를 시작할 수 있습니다.
- 향후 ChatGPT 계정 연결·해제나 export 같은 고위험 작업에도 같은 문제가 생깁니다.

최소 수정안:

- 계정 삭제, 전체 export, 외부 모델 계정 연결·해제에는 최근 인증 또는 Google 재인증을 요구합니다.
- 명시적 확인과 짧은 작업용 nonce를 사용합니다.

검증:

- 오래된 세션, 재사용 nonce, 병렬 삭제, 재인증 취소 및 삭제 중 callback 시험

## 4. 설계상 닫힌 위험과 열린 쟁점

### 현재 문서에서 설계 수준으로 상당히 닫힌 위험

- Google OIDC 서버 code flow, state/nonce/PKCE, ID Token 검증
- opaque 서버 세션, 쿠키 속성, CSRF·Origin 검사
- client 신원·role·소유권 불신과 객체별 BOLA 방어
- SSE URL에 bearer token을 넣지 않는 계약
- 공고 revision, 접수상태, 실행상태, 최신성의 축 분리
- 서명·credential 포함 fetch URL과 공개 canonical URL 분리
- 임의 URL 수집 금지, SSRF·redirect·DNS/IP·proxy 경계
- PDF 파서 격리와 CPU·메모리·시간·문서 수 상한
- 원문 버전→passage→요건→claim→evidence 추적
- 구조적으로 유효한 인용과 의미상 유효한 인용의 구분
- 필수조건 불명확 시 `SUITABLE` 금지, 필수 충돌일 때만 `UNSUITABLE`
- 실행·판정·최신성 축 분리, terminal 상태 불변
- PostgreSQL lease/CAS/idempotency를 이용한 worker 복구
- `disabled/fake/approved_remote` 분리와 fake 결과 비홍보
- 사용자 API key·개인 Codex 세션·공용 계정 우회 금지
- 프로필 최소수집, 원문 제3자 정보 마스킹 게이트
- 계정 삭제 시 세션·worker 차단, 새 내부 ID, 별도 삭제 저널
- 백업 복원 시 삭제 저널 선적용
- 미측정 정확도·RPO/RTO·보안 상태를 달성했다고 주장하지 않는 원칙

이는 구현이나 테스트로 닫힌 위험이 아니라, 설계가 올바른 방향의 명시적 계약을 보유한다는 뜻입니다.

### 여전히 열린 설계 쟁점

- 현재 유효 revision과 접수 가능 상태의 결정적 projection
- 부분·무음 추출을 막는 문서 완전성 상태
- 열린 SSE 연결의 즉시 권한 철회
- 비신뢰 원문의 브라우저 출력 안전 계약
- 후속 질문·답변의 개인정보 및 회사정보 제한
- 출력·재시도·resume을 포함하는 예산 ledger
- 사람 의미 검토자의 권한과 사용자-facing 신뢰 수준
- 고위험 계정 작업의 최근 재인증
- PDF-only 범위가 실제 공고에서 제공하는 문서 커버리지
- LLM이 없을 때 제공되는 제품을 최종 AI 목표와 혼동하지 않는 제품 범위

## 5. 외부 사실 검증 보류 상태

다음 항목은 `UNVERIFIED`입니다. 이번 검토에서는 설계 결함으로 자동 분류하지 않았습니다.

- 제공된 원문과 Git commit SHA의 실제 일치
- 전역 control/handbook 정책과의 정합성
- 나라장터 실제 natural key, 차수, 정정·취소 코드, 마감 시간대
- API의 pagination, partial failure, rate limit 및 schema drift 동작
- 실제 첨부 식별자, 공식 다운로드 호스트, redirect/CDN 구조와 파일 분포
- 공고·RFP의 저장, 최소 인용, 재배포, 임베딩, 외부 LLM 전송 이용조건
- Google OAuth 운영 앱 등록, redirect/origin, 쿠키 및 검증 요구
- Sign in with ChatGPT/Codex의 현재 공개 원격 호스팅 참여 자격과 승인
- ChatGPT 플랜으로 제공되는 모델·한도·철회·사용량 정보와 비용 처리
- provider 토큰 저장·갱신·동의 scope·계정 연결 흐름
- provider 입력·출력 보존 및 학습 이용 정책
- 실제 호스팅, reverse proxy 신뢰 범위, secret 저장소, 백업 저장소
- 파서 런타임의 실제 네트워크 차단, OS sandbox, 자원 제한 효과
- 초기 10/20MiB, 180초, 토큰·호출 수, RPO/RTO 값의 현실성
- 평가 baseline과 공개 품질 임계치

특히 LLM 원격 연동 미승인은 외부 사실이자 최종 제품 목표의 출시 차단 조건이지만, 문서가 이를 정직하게 비활성화하고 있으므로 그 자체를 설계 결함으로 보지는 않았습니다.

## 6. 먼저 할 5가지

1. `EffectiveNoticeProjection`과 마감·정정·취소·freshness의 fail-closed 진리표를 ADR-002/007에 추가합니다.
2. `extraction_completeness`를 도입하고 부분·스캔·표 누락 문서는 무조건 `NEEDS_REVIEW`로 전파합니다.
3. SSE 지속 권한 재검사와 React의 plain-text/safe-link 렌더링 계약을 명시합니다.
4. 후속 질문·답변 allowlist, 의미 검토자 권한, 전체 budget ledger를 설계 계약과 테스트 계획에 추가합니다.
5. 이후에만 실제 나라장터 read-only 표본, 첨부 이용조건, Google OIDC, 공개 원격 LLM 자격을 공식 출처로 검증하고 제한적 PoC를 구현합니다.
