## 승인·원본 없이 가능한 것과 불가능한 것

- **완료:** 공개 소스의 합성 회귀(P04~P09), 공식 문서 검토를 위한 원문 근거/메타데이터 UI, 기존 감사 라벨·이력 보존 장치 및 비식별 집계 API. Codex 합성 검수/CI/Windows 적용은 별도 보고에 기록.
- **NOT VERIFIED:** 실제 PDF/HWP 전체 페이지, 표·각주·이미지 OCR의 내용 완전성, 참가자격·평가기준·과업 요구사항의 독립 정답과 실제 TP/FP/FN, 회사 면허·실적·가용 인력·원가, 실제 사용자 화면 최종 승인.
- 실제 회사 자료를 외부 LLM·공개 저장소로 전송하거나 사용자 대신 입찰/서명/계약하지 않는다. 없는 공식 첨부를 임의로 재구성하거나 근거가 부족한 항목을 자동 PASS로 바꾸지 않는다.

## 실제 원본 비교 시 실행 순서

1. 사용자가 허용하는 공고와 해당 최신 공식 첨부 PDF/HWP를 **Windows 로컬에서만** 선택한다. 차수·취소·STALE·첨부 identity와 SHA를 먼저 대조한다.
2. 우선 표본은 중복되지 않게 검토 위험이 큰 **절단·경고·구형 근거**부터 선정하고, 정상 추출 항목도 포함한다. `READY_TO_FETCH` 상태는 텍스트 정답 평가 대상으로 세지 않고 원문 확보 대기로 분리한다.
3. 사람 검수자는 원본 전체에서 참가자격/면허·공동수급, 평가기준/배점, 과업 범위의 *정답 구절*을 독립 식별한다. 목차·계약 관리 문장·단순 안내와 실제 요건을 구분한다. 원본 페이지, 표/각주/OCR 여부, 최신 문서 차수, 정답 분류와 판단 근거를 **로컬 승인 자료**에 기록한다.
4. 각 실제 문구 후보를 원본 구절과 대조하여 TP, FP를 표기하고, **모델이나 키워드 탐지가 전혀 하지 못한 독립 정답 구절은 FN**으로 기록한다. 근거 미확인·원본 부재·분류 이견은 `UNKNOWN`으로 분리하고 임의 점수화하지 않는다.
5. 분류별 precision=`TP/(TP+FP)`, recall=`TP/(TP+FN)`. 분모가 0이거나 원본 일부만 확보됐다면 `NOT_ESTIMABLE`. 표본의 점수는 전체 공고 성능으로 일반화하지 않는다.
6. 회사 적격 검증은 승인된 사업자등록/면허·실적증빙·기술·가용 인력/일정·원가 각각을 **출처/유효일/공고별 충족 여부/검토자**로 분리하여 체크한다. 필요한 원문이 없으면 `UNVERIFIED` 유지.
7. 종료 전에 원본 파일 및 기존 판단·감사 라벨·RFP 캐시의 해시/개정 충돌/복구 상태를 확인한다. 승인된 조치만 적용하고 잘못된 라벨 수정 시 과거 이벤트는 보존한다.

## UI 검토 절차 / 사용자 결정

- Windows PC `http://127.0.0.1:8765/decision-preview`에서 공고 전체 상세 → 참가자격·과업 확인 → RFP 원문 표현·출처 근거 → 라벨 검토로 진행한다.
- 사용자가 실제 업무 문서의 **원문 정확성·검토 가능한 UX**를 확인한 뒤 UI 인수 결과를 결정해야 한다. 합성 Chrome E2E PASS는 사용자 승인으로 자동 승격하지 않는다.
- P10 `main` 병합·인터넷 공개는 별도 명시적 승인, 인증/보안·라이선스/NOTICE·운영 책임자/복구 계획이 충족될 때만 재개.
