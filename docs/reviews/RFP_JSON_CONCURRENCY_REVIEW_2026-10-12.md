# RFP JSON 프로세스 간 쓰기 경합 검증 - 2026-10-12

## 목적·검수 범위
- 실제 문제: `dashboard.json`과 `rfp_batch.json`의 `os.replace`는 단일 쓰기 원자성만 제공하며, 서로 다른 프로세스에서 읽은 구버전을 늦게 저장하면 변경이 유실된다.
- 범위: `local_app/json_transaction.py`, `server.py`, `rfp_batch.py`, `dashboard_backend.py`, 합성 단위/HTTP/다중 프로세스 테스트.
- 해결: 운영체제 파일 잠금으로 저장 작업의 read-modify-write 일관성 보호, 별도 배치 작업자 독점 임대, 비정상 종료 복구, 공식 재수집 첨부 보존, 늦게 도착한 구형 문서 추출의 수정 충돌 방지.
- 비공개 실제 `dashboard.json`/`rfp_batch.json`/`cases.json`/`workforce.json` 및 인증키를 독립 리뷰 입력에 포함하지 않는다. 개발/테스트는 합성 임시 디렉터리에서만 수행한다.

## 검증 규약
- 대표 실패 유형: 두 프로세스의 동시 대시보드 변경 유실, 두 배치 관리자의 동일 대상 중복 요청, 잠금 시간 초과, 작업자 프로세스 강제 종료, IN_PROGRESS 복구, 한 인스턴스의 pause를 다른 인스턴스가 존중, 공식 재수집 후 기존 RFP 첨부·사람 판단 보존, 늦게 끝난 구형 문서 추출이 최신 문서를 덮어씀.
- 합성 fixture 결과와 실제 사용자 데이터의 불변성은 별도로 확인한다. 코드 테스트는 전체 운영 안전성·입찰 적격성의 증명이 아니다.
- 파일 잠금의 보장 범위는 동일 로컬 파일시스템의 협력 Python 프로세스이다. NAS/네트워크 파일 공유 잠금, 수동 파일 편집기, DB 다중 트랜잭션, 실제 대량 RFP 재수집은 범위 밖.
- 독립 리뷰 결과, finding disposition, 전체 unittest/CI는 실행 결과를 확인한 뒤 갱신한다.
