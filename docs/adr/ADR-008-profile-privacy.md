# ADR-008 사용자 프로필·개인정보 수명주기

- 상태: **최소수집·보안 원칙 채택(법적 고지·운영 구현 검증 전)**
- 관련 지적: DSR-011
- 원칙: 공개 포트폴리오이므로 기업/사람의 민감한 비공개 정보 없이도 유용한 분석이 가능하도록 한다.

## MVP 데이터 범위

| 구분 | 입력/저장 정책 |
|---|---|
| 계정 | 검증된 OIDC issuer + `sub`와 서비스 내부 사용자 ID만 필수. 이메일/이름은 꼭 필요할 때만 별도 동의·최소 저장 |
| 기업 프로필 | 사용자 선택 기술 스택, 수행 가능한 업무 유형, 보유 인증의 **존재 여부** 등 비민감 최소 필드 |
| 사업체 정보 | 사업자등록번호, 대표자 주민등록번호, 담당자 연락처 등은 MVP 수집하지 않음 |
| 내부 자산 | 고객사 제안서·영업비밀·회사 내부 코드·계약서는 업로드하지 않음 |
| 분석 기록 | 공개 공고의 version/hash, 가명화된 user ID, 요건별 상태, 근거 ID, 분석 시각 |
| 로그 | request ID, 오류 유형, 최소화된 운영 지표. cookie/token/전체 프롬프트·프로필 원문 기록 금지 |

## 데이터 처리 원칙

1. 프로필 입력 단계에서 저장 목적과 외부 모델 전송 가능성을 알려준다. 외부 모델 연결 기능이 실제로 승인되기 전에는 사용자 프로필을 외부 모델로 전송하지 않는다.
2. 외부 AI가 활성화되면 `LLM allowed fields` 명시 allowlist를 적용하며, 분석에 필요한 정보만 보내고 전송 범위·제공자·삭제 정책을 고지한다. 개인·회사 기밀은 전달하지 않는다.
3. 일반적인 사용자 프로필은 계정 유지 기간 동안 보존한다. 분석 결과는 최초 MVP 정책값으로 **30일 보존** 후 삭제하되, 실제 서비스 고지와 동기화한다.
4. 사용자는 언제든 프로필 삭제·계정 삭제를 요청할 수 있고, 활성 DB·분석 이력·파생 캐시·vector 검색 데이터·미완료 run을 연결된 식별자로 삭제 또는 무효화한다.
5. 운영 백업은 접근 제한·암호화하며 최대 **30일 회전 보존**을 초기 정책값으로 둔다. 삭제 요청 당시 백업 데이터는 만료 시 파기하고 복원 시 삭제 목록을 다시 적용한다.
6. 서드파티 공공 원천 자체는 개인 데이터와 분리하여 출처별 이용조건에 맞춰 보관/링크한다.
7. 외부 모델 제공자의 입력·출력 보존 및 사용권 정책은 provider 선정 시 확인하고 사용자 고지에 반영한다. 이 정책을 확인하지 못하면 프로필 외부 전송을 비활성화한다.
8. 사용자별 데이터 export 및 정정 경로, 계정 탈퇴 후 재로그인 처리, 탈퇴 중 진행되는 작업 취소를 설계한다.
9. 법적 의무 보존 등 예외는 실제 근거와 범위를 문서화한 뒤 적용한다. 현재 이 설계를 법률 준수 인증이라고 주장하지 않는다.

## 검증

두 사용자 교차 접근, 계정 탈퇴 중 분석, 삭제 후 profile/run/cache/vector 확인, 보관기간 만료 배치, 백업 복원 후 삭제 목록 적용, 로그·모델 입력 fixture의 민감정보 누락을 테스트한다.
