# ADR-008 사용자 프로필·개인정보 수명주기

- 상태: **최소수집·보안 원칙 채택(법적 고지·운영 구현 검증 전)**
- 관련 지적: DSR-011
- 원칙: 공개 포트폴리오이므로 기업/사람의 민감한 비공개 정보 없이도 유용한 분석이 가능하도록 한다.

## MVP 데이터 범위

| 구분 | 입력/저장 정책 |
|---|---|
| 계정 | 검증된 OIDC issuer + `sub`와 서비스 내부 사용자 ID만 필수. 이메일/이름은 꼭 필요할 때만 별도 동의·최소 저장 |
| 기업 프로필 | 사용자 선택 기술 스택, 수행 가능한 업무 유형, 보유 인증의 **존재 여부** 등 비민감 최소 필드 |
| 사업체 정보 | 사업자등록번호, 대표자 주민등록번호, 담당자 연락처 등은 MVP 수집하지 않음 |
| 내부 자산 | 고객사 제안서·영업비밀·회사 내부 코드·계약서는 업로드하지 않음 |
| 분석 기록 | 공개 공고의 version/hash, 가명화된 user ID, 요건별 상태, 근거 ID, 분석 시각 |
| 로그 | request ID, 오류 유형, 최소화된 운영 지표. cookie/token/전체 프롬프트·프로필 원문 기록 금지 |

## 데이터 처리 원칙

1. 프로필 입력 단계에서 저장 목적과 외부 모델 전송 가능성을 알려준다. 외부 모델 연결 기능이 실제로 승인되기 전에는 사용자 프로필을 외부 모델로 전송하지 않는다.
2. 외부 AI가 활성화되면 `LLM allowed fields` 명시 allowlist를 적용하며, 분석에 필요한 정보만 보내고 전송 범위·제공자·삭제 정책을 고지한다. 개인·회사 기밀은 전달하지 않는다.
3. 일반적인 사용자 프로필은 계정 유지 기간 동안 보존한다. 분석 결과는 최초 MVP 정책값으로 **30일 보존** 후 삭제하되, 실제 서비스 고지와 동기화한다.
4. 사용자는 언제든 프로필 삭제·계정 삭제를 요청할 수 있다. **계정 삭제 트랜잭션**은 actor의 모든 세션·진행 중 OIDC 인증 시도 폐기, 실행/질문 취소, 사용자 자료에 대한 신규 작업·접근 거부를 먼저 실행하고, DB·분석 이력·파생 캐시·vector 검색 데이터 삭제를 안전하게 예약한다.
5. 운영 백업은 접근 제한·암호화하며 최대 **30일 회전 보존**을 초기 정책값으로 둔다. 삭제 요청 당시 백업 데이터는 만료 시 파기하고, **활성 DB 백업과 분리된 접근 통제·복원 경계**에 삭제 저널을 보관하여 오래된 백업을 복원한 뒤에도 삭제 요청을 먼저 다시 적용한다.
6. 서드파티 공공 원천 자체는 개인 데이터와 분리하여 출처별 이용조건에 맞춰 보관/링크한다.
7. 외부 모델 제공자의 입력·출력 보존 및 사용권 정책은 provider 선정 시 확인하고 사용자 고지에 반영한다. 이 정책을 확인하지 못하면 프로필 외부 전송을 비활성화한다.
8. 사용자별 데이터 export 및 정정 경로, 계정 탈퇴 후 재로그인 처리, 탈퇴 중 진행되는 작업 취소를 설계한다.
9. 법적 의무 보존 등 예외는 실제 근거와 범위를 문서화한 뒤 적용한다. 현재 이 설계를 법률 준수 인증이라고 주장하지 않는다.

## 검증

두 사용자 교차 접근, 계정 탈퇴 중 분석, 삭제 후 profile/run/cache/vector 확인, 보관기간 만료 배치, 백업 복원 후 삭제 목록 적용, 로그·모델 입력 fixture의 민감정보 누락을 테스트한다.

## 계정 삭제·재가입·백업 복원 계약 — R2-007

1. `DELETE_ACCOUNT` 실행 시 DB에서 계정 상태를 `DELETING`으로 원자 변경한다. 즉시 서버 세션 전체를 무효화하고, 미완료 OAuth 로그인 시도·사용자별 실행 lease·대기 질문·SSE 구독/취소 요청을 차단한다.
2. 비동기 삭제 작업이 끝날 때까지 신규 요청·로그인으로 이전 사용자 리소스에 접근할 수 없다. 기존 인증 콜백은 삭제 중인 사용자와 연결되면 폐기한다.
3. 동일한 Google `issuer + sub`로 재가입하더라도 **새 서비스 내부 `user_id`를 부여**하고 이전 분석·프로필·근거/작업 소유권과 자동 연결하지 않는다. 삭제된 계정의 이전 매핑은 파기한다.
4. 삭제 저널은 이전 **내부 사용자 UUID와 삭제 대상 리소스/저장소 식별자**, 삭제 요청의 적용 시각과 완료 상태를 최소한으로 저장한다. 원문 Google `sub`, access token, 연락처는 저널에 남기지 않는다.
5. 저널은 복원될 DB 백업과 별도 보호 영역(접근 제한·암호화·감사 기록)에 보관하고, 모든 해당 백업이 만료되고 파기 검증되기 전 삭제하지 않는다. 데이터 복원 시 **공개 접근 재개 전** 복원 DB에 삭제 저널을 재적용하여 복원된 과거 세션·자격증명·소유권 매핑이 활성화되지 않도록 한다.
6. 삭제가 일부 실패하면 `DELETING`을 유지하고 권한을 차단한 채 재시도/운영 조치를 기록한다. 성공하기 전 삭제 완료라고 주장하지 않는다. 백업에서의 완전 삭제 시점은 명시적 운영 안내의 범위 내에서 표시한다.
7. 실제 법적 보존이 필요한 예외는 분리된 근거, 범위, 파기 시한을 명시해야 하며 기본적으로 추정하지 않는다.

## 공식 공개 원문 내 제3자 정보 — R2-006

공공 PDF의 이름·연락처·서명·저자 metadata 등은 이용자가 제공한 기업 프로필과 **별도 처리 분류**다. 공개 URL에 있다는 이유만으로 외부 LLM·벡터 저장/재배포가 허용된다고 가정하지 않는다. 자료 이용조건이 불명확하면 보관·인덱싱·모델 전송을 비활성화하고 공식 링크/허용된 최소 인용만 사용한다. [ADR-006](ADR-006-document-ingestion-security.md)의 개인정보 탐지·마스킹·검증을 적용한다.

검증 추가: 삭제 직후 쿠키·OAuth callback, 삭제 중 worker 결과 저장, 같은 Google 계정 재가입, 삭제 전 백업 복원 후 저널 재적용, 연락처/서명 포함 합성 PDF의 DB·검색 인덱스·LLM payload 검사.

## 후속 질문·답변 개인정보 inventory — R3-005

- `Question` 및 `Answer`는 별도의 **사용자 소유 데이터**다. `run_id`, 승인된 질문 type/enum, 비민감 응답 code, 작성/만료 시각, provenance만 저장하며 자유 텍스트/업로드/내부 URL/민감한 회사자료 입력을 허용하지 않는다.
- 질문/답변은 분석 이력과 같이 초기 30일 보존·탈퇴 즉시 접근 차단·삭제/백업 저널/수출(export) 규칙을 적용한다. 질문이 종료되거나 무효화된 경우에도 제한된 기간 이상 보관하지 않는다.
- LLM에는 승인된 비민감 enum 값·요건 식별자만 제공하고 원시 자유 텍스트를 전송하지 않는다. 사용자가 제공한 응답은 여전히 self-declared fact이며 검증된 자격의 근거로 표시하지 않는다.
- 입력 화면과 서버 스키마에서 사업자·개인 식별번호, 고객·거래처 명단, 재무원문, 계약서·제안서·인증정보, 비공개 프로젝트명/URL을 요청하거나 수집하지 않는다. 관련 내용을 요구하는 RFP는 사용자에게 공식 자료를 별도 확인하도록 안내한다.
- 재검증: 질문 타입 allowlist 우회/임의 모델 출력, 사용자 선택값 변조, 개인정보 포함 악성 응답, 계정 삭제·backup restore 이후 Q/A 노출 차단.


## 사용자 제공 값의 출처와 행정 자격 판단 — R4-004

- 기업/기술 프로필의 각 `ProfileFact`는 `SELF_DECLARED/EXTERNALLY_VERIFIED/UNKNOWN` 출처 및 확인일·허용 증빙 범위를 기록한다. 일반 사용자 입력과 후속 질문 예/아니요는 반드시 `SELF_DECLARED`.
- 보유 기술·경력·자격 자체를 증명할 수 없는 MVP에서는 '입력한 프로필과 공고 요건의 일치'만 계산한다. 이를 공식 입찰 참가자격 검증으로 표기하거나 법적 필수 자격의 공식 `SATISFIED`로 자동 승격하지 않는다.
- 별도의 신뢰 가능한 외부 검증 수단을 승인/구현하지 않는 한 행정적 필수요건은 `NEEDS_REVIEW`로 처리한다. 화면에 자기신고와 외부 검증을 시각적으로 구별한다.

## 외부 모델 요청이 이미 전송된 뒤의 계정 삭제 — R4-006

- 삭제 상태 `DELETING`이 되면 **신규 외부 모델 전송을 중지**하고 이미 요청한 provider 호출은 사용 가능한 공식 취소 수단으로 취소를 시도한다.
- 삭제 직전 전송된 외부 모델 요청은 서버에서 철회하지 못하거나 제공자가 일부 기간 보존할 수 있다. 이 경우 늦은 모델 결과는 DB·로그·인덱스·SSE에 저장하거나 사용자에게 전송하지 않는다.
- 개인정보를 넣지 않은 `provider_dispatch_id`와 `run_id`만 내부 삭제 처리 작업에 연결하며 토큰·프롬프트 원문·개인정보를 이력에 남기지 않는다.
- 사용자 표시를 `LOCAL_DATA_DELETED`와 `EXTERNAL_PROVIDER_RETENTION_PENDING/UNKNOWN/CONFIRMED`로 구분한다. 공급자의 데이터 처리·보존 계약으로 확인하지 못했다면 외부 데이터까지 즉시 완전히 삭제되었다고 주장하지 않는다.
- 외부 제공자의 실제 보존 정책, 처리 지역, 취소·삭제 처리 지원을 확인하기 전에는 사용자 프로필 전송 기능을 활성화하지 않는다.
- 검증: 외부 호출 전후 및 결과 도착 직전의 삭제 요청, 취소 미지원/실패, late reply가 DB·캐시·로그·SSE에 없는지, 백업 복원 후 삭제 상태를 확인한다.
