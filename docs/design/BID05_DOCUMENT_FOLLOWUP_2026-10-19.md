# BID-05 공식 문서 후속 작업 큐 설계

- 기준: 실제 branch/HEAD bd1c072, 추적 변경 없음. 기존 비공개 승인 메모 유지. 앱 작성 중인 다른 동일 저장소 세션 없음. 기존 BID-04/공통 정책·합성 인수 구조 재사용.
- 범위: 새 고정 GET `/api/dashboard/bid-document-queue`와 후보 화면의 명시적 조회. 기존 rfp-review-queue 의미와 분야 필터를 유지한다. 새 큐는 전체 공식 보관 공고를 보고 역량/분야 불일치를 제거하지 않는다. 취소/구차수/마감/상태 불명/identity·버전·SHA 불일치는 별도 보류 목록과 건수로 보존한다.
- 분류: 공식 첨부 없음/다운로드 대기·실패/추출 실패/실패 단계 불명/부분 추출/잘림/경고/정정 재확인/버전·SHA·캐시 결속 미검증을 고정 코드로 구별한다. 과거 일반 FAILED는 실패 단계를 추정하지 않는다. 향후 사용자가 승인한 기존 batch 실행만 다운로드/추출 실패 단계를 별도 메타데이터로 기록한다. 성공 재사용·시도 한도·기존 저장/이력 의미는 유지한다.
- 우선순위: 마감 <=24h/<=72h/이후와 미확인, 무결성 위험의 긴급성, 같은 긴급도·기한에서의 확인 비용 순위로 결정한다. 비용은 LOW/MEDIUM/HIGH/UNKNOWN 확인 작업 등급이며 실제 원가/MM/수익 점수가 아니다. 취소·과거 차수·마감은 배치 대상 추천과 분리하고 재시도하지 않는다.
- 공식 결속: 기존 g2b URL 검증과 URL+파일명 identity, 공고번호/차수, source SHA·content-addressed fulltext/chunk hash를 메모리에서 대조한다. SHA/경로/첨부명/본문을 응답하지 않는다. 최신 공식 사이트나 원본 binary 재접근 없이 동일 URL 내용 변경을 알아낼 수 없으므로 공식 최신성·binary 재검증은 항상 UNVERIFIED다. 정정/STALE·충돌은 예전 성공 결과를 유지하면서 재평가 차단한다.
- 읽기 경계: BID-04의 제한 JSON 캡처·release metadata·전후 안정성 검사 재사용. 새 캐시 읽기는 경로/링크 거부, 고정 hex 참조, 512KiB/파일·128파일·총32MiB 상한·strict JSON·전후 bytes 검사로 제한한다. 상한은 명시적 미검증 신호, 오류/변경은 고정 503이며 0건으로 위장하지 않는다. 캐시는 메모리 hash 검증만 하며 새 파일/잠금/분석/LLM/네트워크/다운로드를 생성하지 않는다.
- 출력: 총 확인 필요/작업/보류/생략 건수, 고정 이유·다음 작업·공식 첨부/추출/버전 결속 상태. local UI에서만 상세 연결에 필요한 검증된 공고 ID를 반환한다. 실제 자료 검증/공개 보고/외부 로그에는 안전한 집계만 기록한다. 양 목록 최대 각30개, 전체10000개 상한, 한 기준시각 고정. 같은 요청 내 관측 안정성은 트랜잭션/공식 최신성 보증이 아니다.
- 재평가: 결속/추출이 온전한 경우에도 STORED_TEXT_ONLY(기존 규칙 텍스트 검토 가능)이며 원본 전체 분석 완료/참가 가능을 뜻하지 않는다. 나머지는 원본/추출 품질 보완 전 차단한다. 법적 자격·수익·인력·MM은 UNVERIFIED/BLOCKED_EVIDENCE, 사람 최종 판단과 검토 이력 불변.
- UI: 명시적 GET, 10초 취소·최신 요청 우선·오래된 목록 즉시 제거. 작업/보류 선택과 건수/선정 근거/위험/다음 작업/재평가 제한 표시. 고정 텍스트 노드·기존 상세로만 연결, 원문이나 오류 본문 삽입 없음.
- 검증: 단위/HTTP(보안·canary·불변·오류), 실제 읽기 전용 집계, 합성 취소/정정/마감/누락/추출 실패/SHA 및 버전 충돌·캐시 상한/변경, 전체 Python/Node, Chrome390/1440, 별도 read-only Codex 최종 검수. GO·같은 SHA 개발2/main CI·백업/복구·운영 API/화면/전체 파일 전후 무결성 뒤 DONE. BID-06은 시작하지 않는다.
