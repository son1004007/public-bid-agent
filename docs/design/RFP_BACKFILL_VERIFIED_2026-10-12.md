# RFP 70건 기존 추출 증거의 안전한 청크 소급 이관

## 배경과 목표
- 2026-10-12 기존 격리 RFP 배치는 마감 전 70건 공고에서 127개 문서의 추출 증거를 기록했다.
- 이 중 많은 문서의 6,000자 초과 부분은 기존 dashboard.json에 저장되지 않았다. 새 `rfp_fulltext.py` sidecar 기능은 앞으로 추출하는 문서에만 적용된다.
- 이번 단계는 이미 EXTRACTED인 문서의 공식 파일을 **제한적으로 다시 내려받고 동일성 확인 후** 청크 참조만 증거에 추가한다.
- 기존 운영 서버(8765) 및 사용자 원본은 건드리지 않고, Windows 개인 PC의 기존 70건 격리 stage를 새로운 별도 비공개 디렉터리에 복제해 검증한다.

## 입력·출력 계약
- 입력: 기존 `dashboard.json`과 70개 공고 ID(기존 `rfp_batch.json`의 target_ids), 공식 첨부 URL/명칭, 기존 `document_evidence`의 SHA-256, identity, chars, excerpt.
- 검사: (1) 기존 document identity = SHA-256(URL + newline + 파일명)가 첨부와 유일하게 일치해야 함 (2) 재다운로드 바이너리 SHA-256 = 기존 파일 SHA-256 (3) 새 파서 출력 문자수와 기존 excerpt 접두부 일치.
- 성공: 문서별 `fulltext_ref` 및 문자수·파서 절단 상태·청크 수만 기존 evidence에 추가. 기존 excerpt, `rfp_text`, 인력·원가, 법적 적격, 사용자 최종 판단·이력은 보존.
- 원문 파일 변경: `SOURCE_CHANGED`; 파서/추출 차이: `PARSER_CHANGED`; 첨부 식별 모호: `UNMATCHED`; 공식 HTTPS 다운로드 장애: `FETCH_FAILED`. 모두 자동 병합 및 사용자 판단 변경 없이 분류.
- 중복 실행: 이전 완료·격리 결과를 `rfp_backfill.json` checkpoint에서 확인하고 건너뛴다. 한 회차 1/3/10/25문서, 직렬 실행 및 최소 3초 지연.
- 무결성: 새 비공개 `rfp_fulltext/<sha>.json` 청크는 `rfp_fulltext.load`로 다시 검사한다. 기본 웹 API에는 청크 원문을 추가하지 않는다.
- 외부 AI·회사 비공개 문서·개인정보 외부 전송은 수행하지 않는다.

## 한계와 보안
- 바이너리 동일성은 **기존에 다운로드한 문서 버전**을 검증할 뿐, 나라장터 공고의 모든 정정·참가자격·최신 게시물 여부를 보장하지 않는다. 정정/취소 상태는 별도 공식 상세 API로 검증해야 한다.
- 파서 출력은 최대 44,000자이며 본문 offset은 실제 PDF 페이지·표/각주 좌표가 아니다.
- 청크 파일은 별도 로컬 평문이며 사용자 PC/파일 권한으로만 보호한다. 공개 GitHub에 문서 원문이나 링크, 회사 비공개 자료, 인증키, 인력 정보는 포함하지 않는다.
- `dashboard.json`과 청크 파일은 다중 파일 원자 commit이 아니다. 중간 실패 시 미참조 sidecar가 남을 수 있다. 기존 evidence를 지우지 않으며 idempotent 저장을 통해 다음 회차에서 복구한다.
- 네트워크 중 변경되면 기존 공고 해시·발췌를 유지하며 추측해서 동등하다고 판단하지 않는다.
- 격리 이관은 기존 운영 8765 적용, AI 입찰 적합성 완료, 사용자 UI 승인 및 출시 승인이 아니다.

## 검증
- `local_app/test_rfp_backfill.py`: 동일 소스 성공, 다른 바이너리/파서 차이 격리, 파일명·URL 식별 불일치, 2회 분할 재개, 중복 재시도 방지와 담당자 결정/이력 불변.
- 사용자 PC 실제 공고는 **별도 격리 stage**에서 실행하고 원본/구 격리 stage 파일의 SHA-256과 청크 해시를 주기적으로 확인한다.
- 결과 및 누락은 별도 `docs/reviews/RFP_BACKFILL_VERIFIED_E2E_2026-10-12.md`에 비식별 집계로 기록한다. 독립 최종 AGY/Gemini 검수, 운영 반영/백업·복구는 별도 게이트다.
