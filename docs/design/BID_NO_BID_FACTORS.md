# Bid/No-Bid 입력 영향인자(설계안)

- 작성일: 2026-10-09
- 상태: 퍼블리싱 검토용 사전 변수 모델; 인자 가중치·임계치는 사용자와 과거 실제 기록으로 검증하기 전 가설
- 현재 구현 파일: `frontend/public/bid-management-preview.html`, 공고별 관리 > **영향인자 평가** 탭
- 입력의 참조문서는 모두 **합성 공고**; 실제 법적 적격성을 판정하는 제품이 아님

## 무엇을 종속변수로 예측/기록하는가

1. `recommendation_y1`: AI/규칙이 내놓는 참여 의사결정 **참고 의견**. 참여 검토/보류/미참여 검토이며 자동 입찰행위가 아님.
2. `final_decision_y2`: 사람의 실제 Bid/No-Bid/보류 결정, 결정자와 이유. AI 점수와 별도로 관리.
3. `actual_outcome_y3`: 회사의 실제 제출/수주/미선정/취소/계약 상태와 근거 및 확정 시점. 공고 단위 낙찰정보만으로 당사 결과를 판정하지 않음.

입찰 수주 가능성(P(win))은 위 입력 점수를 수주확률로 변환한 값이 아님. 충분한 이력, 표본 선택 편향(참여하지 않은 입찰은 실제 수주 결과 관측 불가), 외부 경쟁 요인, 시간 변동을 고려해 별도 통계 검증 전에는 **정량확률 비활성**.

## 1단계: 법률·공고별 필수조건 (Hard gates)

아래 각 항목에 `status=UNKNOWN/PASS/FAIL/NOT_APPLICABLE`, `source_type`, `evidence_ref`, `verified_at`(향후)을 분리.

- 공고별 입찰참가자격 및 등록
- 공고가 요구한 업종·면허·인증
- 공고가 요구한 필수 수행실적·핵심인력·재무
- 공동수급/하도급 허용과 참여 제한
- 제안서·가격서의 실제 마감과 제출방법 충족
- 수행·보안·계약상 명시적 배제 조건 및 수용성

규정·기준은 입찰방식/기관/공고마다 다르다. 어떤 항목도 모든 공고에서 무조건 필수라고 가정하지 않는다. `NOT_APPLICABLE`도 원문 근거 필요. 미충족이 있으면 소프트 점수로 이를 덮어쓰지 않는다. 공동수급 등 적법한 보완 가능성은 인간이 원문 근거로 다시 판정.

## 2단계: 비교·의사결정 영향인자 (Soft factors)

| 항목 | 화면 시연용 가중치 | 높은 점수의 의미 |
| --- | ---: | --- |
| 기술 적합성 | 20% | 요구 기술 구현·검증 가능 |
| 유사 사업 실적 | 15% | 검증 가능한 비교가능 실적 |
| 가용 인력·수행 역량 | 15% | 수행에 투입할 자원 확보 |
| 수익성·현금흐름 | 15% | 추정 원가 대비 건전한 수익 |
| 경쟁 우위 | 10% | 확인된 차별점·약한 경쟁 제약 |
| 전략·고객 적합성 | 10% | 성장 방향·고객 문제와 일치 |
| 제안 준비 여력 | 10% | 시간·자료·제안 품질 확보 |
| 위험 통제 가능성 | 5% | 계약/기술/일정 위험을 통제 |

`rating`은 사용자 1~5점 입력 또는 `UNKNOWN`이며, 근거 출처와 메모를 반드시 함께 기록. 시연 가중치의 합은 100으로 설정. 모든 필수 Gate를 확인하고 8개 평점이 기입된 경우에만 예시 지표 `index=SUM(weight*rating/5)` 산출. **index는 수주 확률도 제안서 실제 심사점수도 아님.** 예시 안내 임계치 75/55는 법적 또는 학술적으로 검증된 기준이 아님.

## 3단계: 공고별 정량 입력

- 예상 매출(만원), 예상 수행 원가(만원), 제안·투찰 준비 비용(만원). 세 값이 있어야 `(매출-원가-입찰비용)/매출`을 *수기 가정 기반*으로 표시.
- 공고상 기술평가·가격평가 배점(%)은 사용자 확인값으로 따로 입력, 하나 이상의 값을 모르면 미확인으로 둠. 실제 배점은 개별 공고/평가표가 기준. 조달청 '협상에 의한 계약' 개요에서 기술/가격 비중 조정 가능함을 안내.
- 향후 독립 정량인자 예: 과거 유사 경쟁 입찰자 수, 계약 기간, 실제 가용 인월, 투찰가격 경쟁도, 외부 파트너 확약, 현금지급 조건. 신뢰 가능한 원천 데이터가 있을 때 추가.

## 4단계: AI 교차검토와 사람의 결정

```text
공식 공고/RFP + 확인된 원문 근거 + 사용자 영향인자
  -> Hard gate 보수적 검증(결정적 규칙, 미확인 보존)
  -> Codex/OpenAI 분석 (독립 관점, 실제 인증 후)
  -> Claude/Anthropic 분석 (독립 관점, 실제 인증 후)
  -> 두 관점의 주장·반론 교환 (라운드 한도/근거 검증)
  -> 합의, 이견, 원문 링크, 추가 증빙 질문
  -> 사용자 최종 선택/사유
  -> 실제 제출/평가/수주 결과와 비교
```

- AI가 개별 점수나 외부 공개자료만으로 법적 자격·낙찰 가능성을 확정할 수 없음.
- 기존 UI의 Codex/Claude 상자는 **실행되지 않은 자리표시자**이며, 실제 Agent 채팅이 아니다.
- 모델별 독립 판단, 스냅샷/프롬프트/모델 버전/근거/검토라운드/최종 서명자 추적은 실구현 시 데이터 계약으로 정의.
- 회사 실제 원가·제안전략·비공개 자료를 공개 GitHub나 외부 모델에 자동 전송하지 않는다.

## 추후 검증 백로그

- [ ] 공고 원문에서 필수 조건/배점과 공고 개정본 추출 시 실제 구조 대조
- [ ] 사용자·회사 프로필의 자체 신고와 공식 문서 검증 구분
- [ ] 실제 공고 10건 이상 표본으로 필수조건 유형의 누락/중복 조사
- [ ] 과거 입찰 이력 확보 시 가중치/임계치 백테스트 (절대 임의 수주율 부여하지 않음)
- [ ] 사용자 평가 입력을 두 AI에 보낼 최소 PII/기업 비공개정보 정책 검증
