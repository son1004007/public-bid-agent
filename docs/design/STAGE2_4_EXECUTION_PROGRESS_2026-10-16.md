# RFP 후속 전 단계 구현·승인 경계 및 다음 작업 (2026-10-16)

## 목적 및 결정

- 사용자 최신 지시: 이전 RFP 원본 검증 후속 작업을 가능한 범위에서 모두 수행하고 적절히 커밋·푸시한다. 미승인 외부 데이터 전송과 실제 계약·입찰은 수행하지 않는다.
- Source of Truth: `AGENTS.md` → `DECISIONS.md` → `AI_CONTEXT.md` → `CURRENT_STATE.md` → `TASKS.md`.
- 작업 순서: 기능 구현 → 합성 정상·오류·보안·충돌 테스트 → Windows 전체 회귀 → Codex 독립 read-only 검수 → 로컬 적용·데이터 보존 확인 → 개발 브랜치 GitHub push/CI. 사용자 UI 승인·main 병합·공개 배포는 별개.
- 비공개 회사 RFP·등록·인력·원가·인증정보는 Codex, 외부 LLM 및 GitHub로 전송 금지. 내부 승인 전 법적 입찰 가능/실제 수익/낙찰 확률은 절대 확정하지 않는다. 기존 7일 API 일시 실패 진단은 D-10에 따라 보류.

## 이번 변경의 보안·기능 설계

### 원본 메모리 대조

- POST `/api/dashboard/rfp-original-compare`: 루프백 Host, Origin, 로컬 CSRF, JSON 크기/인코딩, 원본 8 MiB 제한. 부서 공고 ID와 **기존 증거 identity**로 공식 첨부를 정확히 결속. 다른 버전/중복/취소·구차수/STALE/REVIEW는 판정 보류.
- 원본 파일은 사용자가 기존 로컬 RFP 세부 화면에서 직접 선택해야 하며 자동 다운로드나 저장·공개 전송 없음. 결과는 고정 enum·정수만 반환. 검증이 성공해도 표·각주·OCR·실제 법적 요건은 `NOT_VERIFIED`.
- 로컬 메모리 API는 기존 `write()`의 영구 기록 API와 응답 계약이 다르므로 별도 `fetch`로 처리한다.

### 캐시 재저장 충돌

- `rfp_fulltext.store()`는 완성된 임시 파일을 원자적 hardlink로 등록하여 경쟁 생성 덮어쓰기 방지. 이미 존재하는 캐시의 `reported_chars`/`truncated_by_parser`가 다르면 안전 실패, 기존 파일 보존. 새 RFP 추출 evidence에는 공고 ID·번호·차수 추가. 기존 증거는 차수를 추정하거나 사후 채우지 않음.
- 동일 텍스트·원본 SHA지만 변경된 파서 버전/설정은 검증 불가. `REPRODUCED_TEXT`가 원본 완전성이나 동일 파서 버전을 증명하지 않음.

### 증빙 준비도 / 제출·평가 이력

- GET `/api/dashboard/readiness?id=...`: 운영자료 확인표 `registrations`, `past_performance`, `utilization`, `finance`, `pipeline`, `risks`의 **상태만** 응답. 금액·직원 코드·요약문·증빙 파일명은 응답하지 않음. 모든 실제 적격·이익·기술 결과는 `UNVERIFIED`.
- POST `/api/dashboard/outcome`: 인간 `bid` 결정이 기록된 공고만 `SUBMITTED` 시작 가능. `EVALUATED`, `AWARDED`, `NOT_AWARDED`, `WITHDRAWN`은 허용된 상태 전이와 유효한 확인일·자료 설명으로만 수동 갱신. 점수 0~100 최대 소수 둘째자리, 사용자 주장 `HUMAN_DECLARED_UNVERIFIED`. 대시보드 revision 충돌 409, 기존 `final`, `history`, AI/추천 상태 보존. 실제 나라장터 제출/서명/자동 수주 확정·확률 계산 없음.

## 남은 실제 완료 기준

1. 실제 사용자 PC에서 대표적인 공식 원본 PDF/HWP/HWPX, 일부 OCR·표·각주·44,000자 초과 문서를 합법적으로 확보하고 사용자 PC에서 원본/저장 SHA 대조 및 파서 경고 확인. 실제 파일이 없어 합성 테스트만 통과한 기능은 **운영 원본 검증 완료로 선언 금지**.
2. 독립 페이지/표/각주 원본 정답 라벨과 OCR 품질을 비교해 유실 원인을 `PARSE`/`TRUNCATE`/`CLASSIFY`/`DISPLAY_LIMIT`로 분리하고 3분류 TP/FP/FN 측정.
3. 직무·면허·실적·법적 자격·가용 MM·원가의 실제 확인 문서에 대한 별도 권한·증빙 체계 구축. 현재 내부 직원 등급/가정 급여·참가자격은 추정치. 승인 전 자동 적격·수익 확정 금지.
4. 사용자별 AI provider 동의, 비용/전송 범위, 허용 라이선스·기술스택·해석 출처/재검수 설계와 합성 성능평가. 현재 **외부 회사 문서 LLM 전송 미허용**.
5. 실사용 공고 제출·평가 기록 UI E2E, 복원/롤백, 사용자 데이터 익명화, Chrome 모바일/데스크톱 검수, 독립 보안·운영 릴리스 게이트.
6. 사용자 최종 승인 이후에만 main 병합·외부 인터넷 공개/다중 사용자 로그인 검토. 과거 7일 수집 오류는 D-10 유지.
