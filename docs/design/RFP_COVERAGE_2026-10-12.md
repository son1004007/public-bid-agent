# RFP 원문 확보 상태 진단 - 2026-10-12

## 목적 및 범위
나라장터 공고 수집 → RFP 확보 → 요건 분석 → 업체 역량 비교 → 추천 중에서, 이번 단계는 RFP 확보 병목을 웹에서 확인하는 읽기 전용 기능이다. 새 문서를 다운로드하거나 배치 작업을 자동 시작하지 않는다.

## 구현 계약
- GET /api/dashboard/rfp-coverage: dashboard.json과 department_profile.json을 읽고 선택된 CANDIDATE만 집계한다.
- 전체 후보와 현재 마감 전 OPEN/REGISTRATION_REVIEW 후보를 각각 집계한다.
- 상태는 추출본문 존재, 실패 기록, 공식 지원 링크 대기, 미지원 형식, 공식 링크 없음, 첨부 구조 이상으로 상호 배타 분류한다.
- 공식 링크는 기존 HTTPS 허용 도메인 검사와 SUPPORTED 확장자 목록을 재사용한다.
- 개인별 인력, 원가, 원문, 공고 제목과 첨부 URL은 응답에 반환하지 않는다.
- 문서상태 EXTRACTED는 저장된 텍스트의 존재만 의미한다. RFP 원본 전체 및 최신 개정·표·각주 정확도나 적격성 판단이 아니다.
- 문서 다운로드 오류의 구체 원인은 현재 기록된 정보만으로 재구성할 수 없다. FAILED_ATTEMPT는 해당 상태로 저장된 공고만 센다.
- 기존 /decision-preview 수집관리 화면에 확보 현황·원인별 건수를 표시한다.

## 현재 로컬 읽기 전용 결과
- 공식 저장 공고 총 2,223건 중 선택 부서 후보 143건, 마감 전 후보 110건.
- 전체 후보: 추출본문 39, 공식 지원 링크·추출대기 87, 미지원 4, 공식 첨부 링크 없음 13, 기록상 실패 0.
- 마감 전 후보: 추출본문 38, 공식 지원 링크·추출대기 70, 미지원 1, 공식 첨부 링크 없음 1, 기록상 실패 0.
- user-json의 dashboard.json 및 department_profile.json은 분석 전후 SHA-256 동일.
- 위 값은 실행 시점의 로컬 저장 스냅샷에만 해당하며, 실제 공식 서버 최신 공고 전체나 문서 다운로드 성공 가능성을 뜻하지 않는다.

## 후속 작은 작업
1. 현재 마감 전 공식 지원 링크가 있는 70건부터 격리 배치로 추출 성공/실패 사유를 세분화하며 소수 건씩 검증한다.
2. 실패 사유(공식 링크 만료, 네트워크, 권한 응답, MIME 불일치, 지원 포맷/파서, 빈 본문)를 구조화해 저장하되 키/URL 쿼리/원문 텍스트는 로그에 남기지 않는다.
3. 추출 성공 문서는 전체 표·각주·정정문서를 검증하고, 실제 기술/업체 참가자격/가용 인력과 대조하는 추천 엔진을 후속 구현한다.
4. 로컬 운영 8765 서버 재시작 및 사용자 원본 적용은 백업·복원 게이트와 실제 웹 승인 이후 진행한다.
