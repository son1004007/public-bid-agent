# BID-06 사람 승인 정답과 범위 한정 평가

상태: 설계/구현 진행. 사용자 최신 지시가 이번 작업의 승인 원본이다. 전역 정책 9개 원격 main 확인. 별도 독립 검수는 사용자 지정 순서대로 구현·검증 후 한 번 수행하고 NO_GO 지적만 후속 검증한다. 사전 독립 설계 검수 NOT RUN.

- 기존 추출기와 후보 검토 라벨은 유지한다. 별도 `rfp_ground_truth.json`에 사람이 명시 저장한 표본/수정/보류 이벤트만 추가한다. 기존 원본·추출·사용자 이력 마이그레이션/자동 승인 없음.
- 검수 단위는 한 공식 첨부의 사람이 지정한 원본 페이지 범위와 추출 문자 구간이다. 구간 안 **표시된 기존 추출 후보**를 서버가 캡처한다(유형당5개 상한·생략 수 명시). 사람은 원본에서 세 유형의 독립 정답 구절, 페이지·표/각주/이미지/OCR 위치를 직접 입력한다. 후보를 자동 정답으로 복사하지 않는다.
- 승인은 선택한 로컬 원본 바이트 SHA를 서버가 현재 공식 URL/파일명 identity·공고번호·차수·캐시와 대조한 단기 서명 티켓, 현재 공식 원본/정정·취소 확인에 대한 사람의 명시 확인, 원본 페이지 범위의 표/각주/이미지/OCR 대조 확인이 모두 필요하다. 웹 최신성은 사람이 확인한 사실로만 표시하며 시스템 자동 인증으로 주장하지 않는다. 차수 불명/충돌·SHA 변경·취소·STALE은 재검수. 보류 저장은 독립 정답으로 계산하지 않는다.
- 페이지는 사람이 원본에서 확인한 값이며 추출 offset을 페이지로 환산하지 않는다. 범위 밖 정답 입력/원본 검수 미완료는 승인 거부. 파서 잘림/경고는 계속 표시한다. 원본에만 있는 누락은 수동 정답으로 등록한다.
- 평가: 승인된 최신 표본의 gold와 캡처한 prediction을 세 유형별로 NFC/공백만 정규화한 **동일 구절+동일 분류**의 1:1 일치로 비교한다. 부분 일치는 FP+FN, 분류 오류도 예측 유형 FP+정답 유형 FN, 중복 prediction의 추가 항목은 FP, 같은 위치의 중복 gold는 거부. 경로별 분리는 사람이 지정한 표본 경로(TEXT/TABLE/FOOTNOTE/IMAGE/OCR) 기준이며 자동 파서 경로를 추정하지 않는다.
- 같은 문서/추출 범위가 겹치는 유효 승인 표본은 거부하여 중복 계수를 막는다. 정정은 같은 scope_id의 새 이벤트로 보존한다. 전체 문서 정확도/대표성은 NOT_ESTABLISHED. 승인 정답이 0이면 TP/FP/FN·Precision/Recall/F1/누락률은 null, NOT_EVALUATED. 분모0도 null(전체0인 F1도 null).
- 저장은 기존 Host/Origin/CSRF·release guard·프로세스 간 dashboard transaction·원자적 replace를 재사용한다. expected_revision으로 충돌409, request_id+동일 payload 재전송은 중복 저장 없이 성공, 같은 키 다른 내용409. 제한 JSON·링크 거부·이벤트/파일 크기 제한·고정 오류. 원문/정답/개별 식별정보는 외부 로그/Git에 기록하지 않는다.
- UI: 기존 후보/상세에서 검수 목록·표본 편집·승인/보류·수정·평가·이력 확인. 원본은 사용자 선택 로컬 파일만 메모리 확인, 추출 텍스트와 독립 정답 입력을 나란히/모바일 세로로 제공. SHA/차수는 details 안에 표시. 자동 다운로드/AI/배치/입찰 없음.
- 검증: 합성 범위/표·각주/OCR/부분/중복/오분류/잘림·원본 SHA/버전/서명/권한/충돌·재전송/이력·무변경, 실제 읽기 전용 집계, 전체 회귀, Chrome390/1440, 독립 Codex. GO→개발2 CI→main CI→기존 운영 백업·복귀→API/화면·전후 전체 파일 무결성 뒤 IMPLEMENTATION_DONE. 실자료 승인 정답 없으면 VALIDATION_DONE 아님, BID-06 전체 DONE 금지. BID-07 미착수.
