# 비공개 인력 프로필과 가정 원가 (2026-10-11)

## 목적과 데이터 경계

- 실제 조직의 인원 코드, 직급 분포, 기술 배정, 가정 금액은 사용자 PC의 `PUBLIC_BID_LOCAL_DATA/workforce.json`에만 저장한다. 이 데이터는 공개 GitHub에 게시하지 않는다.
- 비식별 ID라도 역할·등급과 결합하면 작은 조직에서는 재식별 가능성이 있다. 실명 필드 자체를 스키마 검증에서 거부하고 공개 테스트에는 합성 직원만 사용한다.
- GET `/api/workforce`는 127.0.0.1 전용 읽기 API이다. 없을 때 NOT_CONFIGURED, 손상 시 HTTP 503, 회사 자격/인력 가용을 확인했다고 주장하지 않는다.
- 기술과 담당분야는 사용자가 최종 확인할 때까지 ASSUMED, 가용 MM은 `null`이다. 팀장 표기는 별도 내부 역할이며 공식 발주처 인력 등급 또는 입찰 참여 적격 판정으로 전환하지 않는다.
- X·Z처럼 등급/가정원가를 제공받지 않은 비기술 인력은 연봉 원가 합계에서 제외되며 0원으로 간주하지 않는다.

## 계산과 연계

- 가정 원가 = 해당 등급의 연봉 가정 / 12 (원 단위 반올림). 직원별 실제 연봉/실제 기업 총원가가 아니다.
- 사업별 투입은 기존 `/api/operations`, `/api/cost-plan`의 직무별 금액·공수로 분리한다. 인력 프로필 조회는 사업별 원가나 공고 기록을 자동 수정하지 않는다.
- `operations.json`이 없을 때에만 별도 로컬 관리자 절차로 `summary(workforce)["roles"]`에서 직무 원가표를 최초 생성할 수 있다. 기존 파일이 있으면 절대 덮어쓰지 않는다.
- `available_mm = null`인 운영 직무는 원가 계산 시 경고 `가용 공수 미정`을 발생시키고 실제 인력 투입 가능 여부가 확인될 때까지 NEEDS_REVIEW로 남긴다.
- 산출 원가는 퇴직급여, 법정 사용자 부담금, 임원/경리, 간접비, 위험충당, 외주비 등 빠진 항목을 별도 검증해야 한다. 예상이익은 사업별 투입공수 및 부대비용 입력 뒤에도 참고치일 뿐이다.

## 보안과 운영

- 공개 소스 `.gitignore`에 `**/workforce.json`, `**/operations.json`을 추가하였다. Git 이력·PR·로그에 로컬 파일 내용을 복사하지 않는다.
- 업무상 인력 프로필을 개인 장비에서 사용할 수 있는 권한, 보관 기한, 사내 승인 범위는 별도 확인한다.
- Codex/Claude의 입찰 공고문 프롬프트에 인력 코드·원가표를 포함하지 않는다.
- 조직 인원 실명 매칭·가용 일자·자격증·경력·발주처 자격 검증은 아직 구현/검증 대상이다.
- JSON 다중 프로세스 경쟁 쓰기 위험은 기존 RFP 독립 검수 잔여 이슈다. 향후 거래성 기록과 장기 큐는 SQLite의 트랜잭션 또는 검증된 OS 파일잠금 구조로 옮기는 것을 우선한다.
