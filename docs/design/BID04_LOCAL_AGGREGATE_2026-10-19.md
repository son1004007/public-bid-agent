# BID-04 로컬 읽기 전용 집계 설계

## 최신 사용자 확장: 실제 화면·main·기존 로컬 운영 배포

- 사용자 최신 요청에 따라 기존 CLI를 보존하고 `/api/dashboard/bid-now-audit` GET 및 후보 화면의 전체 공고 위험·증빙 집계를 추가한다. API는 CLI와 동일한 캡처/전후 안정성 검사·고정 코드·비식별 집계만 사용한다. 오류는 503, Host 거절은 403이며 입력/스냅샷 실패를 0건으로 바꾸지 않는다.
- 화면은 명시적 집계 버튼으로 GET, 10초 timeout·이전 요청 취소·최신 응답 우선, 전체/활성/보류/무효·마감 구간·취소/구차수/STALE·설정/역량/MM/원가 증빙 부족을 표시한다. 분야 비교 불명은 부적격/보완 확정으로 표시하지 않는다. 과거 완료 저널의 현재 세대 미검증도 표시한다.
- 법적 적격·수익성·보완 허용 UNVERIFIED 및 BLOCKED_EVIDENCE는 사업 준비 상태이고 기능 구현/검증 상태와 구분한다. 실제 공고별 자격 확인·실제 입찰/자동 투찰은 하지 않는다.
- GO 후 개발 브랜치 두 CI, main 기존 변경 비교·안전한 병합·main CI를 확인한다. 인터넷 공개가 아닌 기존 소유자 전용 `127.0.0.1:8765`에만 배포한다.
- 배포는 기존 고정 Git 소스 archive/로컬 보호 파일 전체 백업·SHA 검증/기존 서버 정확 PID·소스 확인/소스만 교체하는 절차를 재사용한다. 기존 P04~P09 제목 gate는 새 BID-04 정확 SHA·원격 두 브랜치 일치·두 workflow SUCCESS·main CI 검사로 대체한다. 새 stage가 이미 있으면 재사용하지 않고 차단한다.
- 새 API와 390/1440px 운영 GET 전용 Chrome 인수가 실패하면 기존 검증 소스와 같은 데이터로 복귀한다. 이전 백업/소스 존재 확인 및 실행 실패 복구도 수행하며 데이터 덮어쓰기/복원은 하지 않는다. 로컬 배포 도구 변경은 별도 읽기 전용 최종 검수 범위에 포함한다.
- 기존 작업자가 원본 폴더를 사용하는 동안 UI 확장은 독립 임시 worktree에서만 구현·검증한다. 기존 세션 종료/인계 확인 뒤 충돌 없는 파일만 원본 작업 트리에 반영한다.

## 기존 CLI 설계(아래 HTTP/UI 제외 표현은 CLI 범위)

- 요구: D-20/BID-04. 실제 저장 공고 전체를 현재 KST 기준으로 평가하고 집계만 출력한다. 원본·회사/인력·원가·ID·경로·SHA·오류 원문은 출력하지 않는다.
- 위험: MEDIUM(민감 로컬 파일 조회 경계). 기존 HTTP/UI/수집/저장 경로는 변경하지 않고 독립 CLI와 순수 집계 함수만 추가한다. 새 의존성 없음.
- 입력: 명시한 로컬 데이터 디렉터리의 dashboard.json, department_profile.json, operations.json, workforce.json. 기본 프로필을 만들어 누락을 숨기지 않는다. 최대 공고 10,000건, 파일별 크기 제한, 링크/재분석 지점 거부. 외부 API·문서 다운로드·AI 호출 없음.
- 읽기: 쓰기 잠금을 생성하지 않는다. 4개 파일을 제한된 바이너리 읽기로 캡처하고 평가 후 동일 파일의 존재/파일 identity/메타데이터/바이트를 재확인한다. 변경 관측 시 집계를 버리고 BLOCKED_SNAPSHOT 고정 코드만 출력, 자동 재시도 없음. 이는 관측 구간 안정성 검사이며 동시 다중 파일 트랜잭션이나 공식 최신성 증명은 아니다. 운영 갱신과 겹치면 갱신이 끝난 뒤 다시 실행한다.
- 중단 세대: 고정 release JSON journal/SQLite intent 및 그 sidecar 부재도 함께 캡처·재확인한다. SQLite는 파일을 DB로 열지 않고 제한된 bytes를 메모리 DB에 deserialize한 뒤 query_only/trusted_schema OFF·고정 table/1행 SELECT로만 검사한다. deserialize 미지원은 BLOCKED_INPUT. sidecar 존재, PREPARED/손상/알 수 없는 상태·저널/intent 불일치 시 BLOCKED_SNAPSHOT. SQLite COMPLETED는 expected_new_files의 dashboard.json/rfp_batch.json 두 키·SHA를 메모리에서 대조(값 미출력), VERIFIED intent와 COMPLETED JSON 조합은 기존 정상 전이로 허용한다. SQLite 없이 JSON만 COMPLETED면 LEGACY_COMPLETED_UNVERIFIED로 집계 허용: 기존 정상 수집은 완료 JSON의 과거 SHA를 갱신하지 않으므로 현재 세대 무결성을 증명하지 않는다. rfp_batch.json도 고정 입력으로 읽기 전후 확인한다. 상태 변경/guard_ready 호출 없음.
- 공고 identity/공식 source·차수·중복·동일 차수 모호성·저장 lifecycle와 메모리 재대조 lifecycle 불일치는 별도 일관성 집계 및 보류. 원본을 reconcile하거나 저장하지 않는다. 취소·구차수·STALE·마감·미확인 기한은 활성 검토에서 보류한다.
- 활성 정의: 유효하고 유일한 공식 identity, 저장/차수 대조 CURRENT, 취소 아님, STALE 아님, 미래 마감. 등록기한 경과/누락·불명은 별도 검토 위험이며 법적 자격 확정 아님. 마감 버킷은 KST 고정 시각에서 <=24시간, <=72시간, <=7일, 이후; 전체 메타데이터와 활성 집계를 구분한다.
- 날짜는 시각을 포함한 ISO 형식만 허용하며 공식 저장 메타데이터의 naive 시각은 기존 계약대로 KST, 명시 UTC/양·음 offset은 KST로 변환한다. date-only/불명/범위 초과는 UNKNOWN. 기한 버킷과 활성 판정·기존 분류 함수에는 같은 정규화 시각을 사용한다.
- 출력: 고정 키의 건수와 고정 상태 코드만. 전체 항목=활성+보류+무효 항목, 활성=분야 일치 검토+보완 검토+분야 비교 불명. 부서 프로필이 없거나 공고 분야 형식이 잘못되면 불명으로 보존하며 미일치로 단정하지 않는다. 위험 집계는 중첩 가능. 관심분야 일치는 실제 기술/법적 자격이 아니다. 분야/스킬 부족만으로 기회를 버리지 않는다.
- 전체 기한/위험 건수는 identity가 무효여도 읽을 수 있는 객체 메타데이터 전체를 대상으로 하며 비객체는 무효 항목 수로만 집계한다. 분류 함수가 처리할 수 없는 객체는 무효 보류. 활성 기한은 활성 집합만 대상으로 하고, 일관성 수치는 중복 집계될 수 있다.
- 증빙: 부서 설정 누락/빈 분야/형식 오류, 운영 증빙 출처·확인일·요약 누락/갱신 필요, MM/총원가 미기록, 기술 증빙 미검증은 BLOCKED_EVIDENCE. 현재 workforce v1은 ASSUMED/UNKNOWN만 허용하므로 기술 검증을 주장할 수 없다. 인원/직무별/단가/스킬별 수치나 분포도 반환하지 않는다. 모든 경우 법적 적격·수익·보완 허용은 UNVERIFIED.
- 실패: JSON 손상/중복 키/비유한 숫자/상한 초과/필수 공고 파일 누락·형식 오류는 고정 BLOCKED_INPUT. 선택 증빙 누락/손상은 집계를 유지하고 BLOCKED_EVIDENCE. 원시 예외/traceback/경로 미출력. CLI 종료 0=집계 수행(증빙 보류 포함), 2=입력/스냅샷 실패. --apply/저장 옵션 없음.
- 검증: 합성 시간 경계·취소/차수/중복/불명·형식/증빙·민감 canary·메모리/디스크 불변·변경 감지·CLI 오류/상한. 실제 자료는 CLI 집계만 실행하고 원문을 모델/로그로 가져오지 않는다. 전체 Python/Node/build 회귀, README 두 종 동기화. 별도 Codex 읽기 전용 GO 이후에만 Git 기록, 같은 SHA 두 CI 성공 전 DONE 금지. 차단 시 최신 사용자 지시대로 commit/push 없이 BLOCKERS 기록.
