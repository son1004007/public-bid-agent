- **공개 소스/비공개 운영 자료 경계:** 공고명, 공식 첨부 URL, PDF/HWP 원문/바이너리, 직원·원가·회사 실적, 개인 credential을 GitHub/외부 AI/Codex에 전달하지 않는다. 실제 자료 점검은 사용자의 Windows PC 로컬에서 읽기 전용으로 수행한다.

## 1. 현재 증거와 근본 제약

1. 공식 첨부를 다운로드할 때 `rfp_batch.py`는 원본 bytes의 SHA-256, 추출 근거, 최대 44,000자 비공개 텍스트 청크를 보관한다. **원본 PDF/HWP 바이너리를 영구 보관하는 시스템은 아니다.** 따라서 저장된 캐시만으로 파서가 원본 페이지·표·각주·그림의 모든 텍스트를 읽었다고 확인할 수 없다.
2. 2026-10-16 읽기 전용 이전 실측: 마감 전 부서 후보 180건, 추출 증거 레코드 161개, 절단 13개/공고 12건, 파서가 기록한 미보관 문자 수 차이 657,453자. 이는 원본과 독립 비교한 실제 누락 건수나 필수요건 누락 수가 아니다.
3. 원본이 로컬에서 제공되면 `rfp_original_compare.compare(attachment, proof, loaded_cache, raw_bytes, parser)`로 **공식 링크와 파일명에 결속된 근거 ID, 실제 원본 SHA, 청크 캐시 SHA·참조, 현재 지정한 로컬 파서의 재추출 텍스트 및 절단 상태**를 비교할 수 있다. 원본은 업로드·복사·로그·저장하지 않는 메모리 처리이며 정상 호출 시 신뢰된 로컬 subprocess 파서만 주입한다. 이미 검증된 `rfp_fulltext.load()`의 캐시 객체를 사용한다.
4. `REPRODUCED_TEXT`는 제공한 원본에서 지정된 파서를 다시 실행한 텍스트와 **저장된 추출 텍스트, 신고된 길이/절단 상태가 재현된다**는 좁은 판정. `REPRODUCED_TRUNCATED_PREFIX`는 재현된 것은 **앞의 최대 44,000자뿐**이라는 표시. 증거 5개 fulltext_* 길이·청크·상태 메타데이터도 캐시와 결속한다. **파서 방법·경고·실행 버전/설정·OCR 재현은 `NOT_VERIFIED`**, 원문 페이지/표 셀 관계/각주/OCR/의미적 완전성도 `NOT_VERIFIED`.
5. 공식 링크 변경/정정/취소/구차수/STALE 반영을 우회해 비교 결과로 해당 입찰 참가 가능성을 확정하면 안 된다. 같은 SHA 비교 성공은 '최신 공식 원본'의 독립 확인과 다르다.
6. **주의:** 동일 원본 SHA + 동일 텍스트를 다시 `rfp_fulltext.store()`하면 기존 청크를 재사용한다. 파서 메타데이터(전체 문자 수·절단 상태)가 다르게 들어왔을 때 기존 청크 기록과 새 응답의 메타데이터가 달라질 수 있다. 이번 작업은 기존 운영 캐시나 저장 정책을 변경하지 않고, 관련 재현 테스트·정책 설계 후 별도 수정한다.

## 3. 현재 단계 이후 다음 작업 우선순위

- 우선 **현재 엔진의 실사용 원본 획득 가능성 점검**: 예전 공고의 원본 바이트는 청크만으로 복원할 수 없으므로 현재 공식 원본과 기존 SHA가 같은지부터 검증. 불일치·STALE 상태면 사용자가 판단하기 전까지 결론 보류.
- 다음 **PDF 페이지별·HWP/HWPX 표/각주·OCR 가시화** 및 사람이 직접 비교 가능한 근거 화면. PDF 텍스트 줄이 전체인 것처럼 오인하지 않도록 이미지 전용/일부 OCR 페이지를 별도 기록.
- 이어 독립 정답 샘플로 3분류 FP/FN을 계산하고 누락 원인이 '파싱/잘림/분류/화면 상한' 중 어디인지 구분. 비교 실패 시 기존 참여 결정은 보존한다.
- 장기 개발 단계는 2절 순서로 실행. **변경된 결정**이 있을 때만 `DECISIONS.md`에 D-ID 추가하고, 구현 결과는 `CURRENT_STATE.md`와 `TASKS.md`를 갱신한다.
